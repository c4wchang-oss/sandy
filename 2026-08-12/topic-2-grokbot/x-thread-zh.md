# X / Twitter 推文串 — Grok Bot：像人類一樣使用你介面的 AI Agent
**日期**：2026 年 8 月 12 日  
**主題**：xAI 推出 Grok Bot——有自己電腦的 AI 隊友，像使用者一樣操作 app  
**格式**：8 則推文串  
**語言**：繁體中文

---

**推文 1（鉤子）**
xAI 剛推出 Grok Bot：AI 隊友，「有自己的電腦」，在你的工具裡 24 小時工作。

這份公告裡埋著一個沒有人在討論的 UX 問題。

🧵

---

**推文 2**
Grok Bot 不用 API，它用你的 UI。

它點擊、讀螢幕、填表單、在 app 之間導航。

這是一個 agent，以和你的使用者完全相同的方式操作你的產品。

---

**推文 3**
為什麼這改變了設計公式：

你的使用者可以應對模糊性。他們會 hover 確認某個東西是否可點擊，試兩個按鈕，讀周圍的文字。

Agent 不行。不清楚的 affordance 不會產出變通方法——只會產出失敗。

---

**推文 4**
我們花了 20 年讓 UI 對螢幕閱讀器無障礙。

寫 alt text、給互動元素有意義的標籤、確保 tab 順序合理。

我們這樣做，是因為有些使用者需要清晰的語意才能導航。

Agent 需要清晰的語意才能運作。

---

**推文 5**
平行關係很精確：

螢幕閱讀器無障礙：這個元素在沒有視覺脈絡的情況下能表達它的用途嗎？

Agent 可讀性：這個元素在沒有人類脈絡解讀的情況下能表達它的用途嗎？

同樣的問題，不同的時代。

---

**推文 6**
它在哪裡失敗——特定、可預測的模式：

• 「送出」vs「儲存」vs「完成」——agent 需要知道哪個會確認狀態
• Hover 才顯示的動作——agent 通常不能 hover
• 點擊外部就關閉的 Modal——不一致的行為讓 agent 失敗
• 沒有脈絡的「確定嗎？」確認對話框

---

**推文 7**
Senior UX 觀點：讓 AI agent 用起來順的產品，並沒有做什麼特別的事。

他們只是建了語意清晰、模式一致、affordance 誠實的 UI。

這本來就是好設計。Agent 只是在強制執行那個審計。

---

**推文 8**
Grok Bot 還在 early beta，大多數團隊還沒開始為 agent 設計。

但現在值得做的測試：給 agent 你的 app，看它在哪裡卡住。

它卡住的地方——就是你的設計債報告。

你有沒有用 AI agent 測試過你的產品？
