# X / Twitter 推文串 — ProtoPie AI 正式上線 + MCP 發布
**日期**：2026 年 8 月 11 日  
**主題**：ProtoPie AI 正式版（Component AI authoring）+ ProtoPie MCP  
**格式**：8 則推文串  
**語言**：繁體中文

---

**推文 1（鉤子）**
ProtoPie AI 正式上線了（從 beta 畢業）。官方標題是「Component AI authoring」。

真正的故事是 MCP 連接器——以及「AI 現在可以直接讀取你的 prototype，而不只是看截圖」這件事意味著什麼。

🧵

---

**推文 2**
直到現在：AI agent 拿到的是你 prototype 的截圖或文字描述。

ProtoPie MCP：AI agent 現在可以直接讀取互動模型——scenes、layers、components、variables、formulas、states、triggers。

Prototype 本身就是 brief，不是 brief 的圖片。

---

**推文 3**
這在設計到代碼的轉換上改變了一件很具體的事：

Agent 不再需要從視覺輸出去推斷設計意圖，而是直接讀取你已經定義好的結構性意圖。

「我設計的」和「最後被蓋出來的」之間的落差，縮小了一截。

---

**推文 4**
Component AI authoring 是另一個重大升級。

AI 現在可以：
• 把圖層轉換成 component
• 建立並切換 instances
• 覆寫 component variables
• 把多個狀態合併成統一 component

全部用自然語言。這不是生成，是 component 系統管理。

---

**推文 5**
這是行銷文案不會說的部分：

ProtoPie AI 在你圖層命名正確的時候效果最好。

「submitButton」> 「Rectangle 3」

AI 的品質天花板現在跟你的檔案整潔度直接掛鉤。圖層命名不再是個人習慣，它是品質輸入。

---

**推文 6**
@ 提及系統（在提示詞中直接引用特定圖層）是人機協作的正確設計語言。

它強制你說得更精確。

「讓 @submitButton 點擊時變灰」比「讓按鈕變灰」好，原因跟「在 prototype 上標注」比口頭交接好，是一樣的道理。

---

**推文 7**
老實說：ProtoPie 的定位會在 MCP 成為設計到代碼的默認標準時變得更關鍵。

但現在還需要刻意設定，不是無縫接軌。

問題是誰會先在生態系統規模上做到——ProtoPie、Figma 的 prototyping agent，還是別的什麼。

---

**推文 8**
方向是清楚的：

高保真 prototype = 給 coding agent 看的機器可讀 brief。

你蓋 prototype 的方式正在改變——從「讓用戶驗證」，到「也確保 agent 讀得懂」。

圖層命名是一個新的資深設計技能。
