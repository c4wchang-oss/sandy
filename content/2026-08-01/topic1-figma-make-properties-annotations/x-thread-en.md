---

**Tweet 1 — Hook**
Text prompting is about to become the slow way to edit UI.

Figma Make just shipped a properties panel and annotation system.

The way you edit AI-generated code just changed.

🧵

---

**Tweet 2**
Here's what shipped:

→ Properties panel: adjust spacing, typography, layout, z-index, opacity — directly in the Make editor
→ Annotations: mark areas on the canvas and prompt the agent in context
→ DOM tree visible as you work (a layers panel for your code)

No more "please change the padding on the card component."

---

**Tweet 3**
The credit mechanic is smart.

Direct manipulation stages every edit in the prompt box — credit-free — until you apply.

You can try 5 different padding values, test 3 font weights, reorder elements. Zero tokens consumed. Once you're satisfied, you commit.

That's not a feature. That's a design decision about when AI should be involved.

---

**Tweet 4**
Annotations are the more interesting unlock.

Select "Annotate for agent" → mark focus areas on canvas → describe the change in your own words.

"When you hover over this thumbnail, zoom in slightly."
"Fade this button in after a 300ms delay."
"Add a press effect when this button is tapped."

Spatial prompt. Contextual. Precise.

---

**Tweet 5**
Notice what annotations do:

They separate *where* from *what*.

The location is exact (you drew it). The instruction is flexible (you wrote it).

The model stops guessing which element you mean. You stopped writing paragraph-length prompts trying to describe a DOM path.

This is the correct UX for AI canvas editing.

---

**Tweet 6**
The properties panel uses your existing codebase tokens.

Color, typography, spacing — whatever's already defined. You're editing within your constraint architecture, not escaping it.

Code Connect is coming soon, which will link Make directly to your Figma Design components.

Design ↔ code consistency maintained through AI edits.

---

**Tweet 7**
What this changes in practice:

Before: write a long prompt → hope the model interprets it correctly → undo → rewrite → repeat.

After: select element → drag spacing → mark annotation → describe the specific behavior → commit.

The edit loop got tighter. The model is now filling gaps, not interpreting everything from scratch.

---

**Tweet 8 — CTA**
Real headline isn't "new editing features in Make."

It's: AI design editing just went spatial. The era of describing everything in text is ending.

The constraint is still yours — the tokens, the system, the design decisions. The model handles execution.

That's the right division of labor.

What's your current prompt-to-result ratio in Make? Lower than 3 months ago?
