**Tweet 2**
Figma Design Agent 現在支援 Custom Skills。

你描述一個你反覆做的工作流程——「套用這個編輯風格」、「對照 DS 審查這個 component」——它就變成 /your-skill-name，整個組織的每個檔案都可以重複使用。

---

**Tweet 3**
這就是 SKILL.md，但原生在 Figma 裡面。

和 Cursor 的 Field Guide、Notion Skills 3.7、CLAUDE.md 是同一個概念。這個 pattern 已經在每個主要工具裡收斂了。

Skill 是被編碼的設計判斷。不只是存起來的 prompt。

---

**Tweet 4**
Skill 跟 plugin 的區別很重要——這其實是一個產品設計決策。

Skill = 自適應。當你需要 agent 解讀情境、做出判斷時用它。

Plugin = 確定性。當相同輸入應該永遠產生相同輸出時用它。

不要搞混。

---

**Tweet 5**
公告裡被低估的是檔案附件和 GitHub context。

Brief 不再只是文字框了。它由這幾個部分組成：
— 你附加的參考檔案
— Agent 讀取的 GitHub component 結構
— 你的 custom skill 限制
— 畫布上選取的內容

多來源的 brief 是一種新的作者技能。

---

**Tweet 6**
誠實的補充：skill 捕捉的是你在那個 session 做了什麼——不是你想要什麼。

如果產生它的 session 很草率，skill 就會把那個模糊編進去。發佈給組織之前，要認真審查。

---

**Tweet 7**
品質天花板移動了。

不再是「模型能做什麼」。

而是：Skill 定義得有多清楚？參考檔案有多完整？你的 GitHub component 結構有多易讀？

---

**Tweet 8（CTA）**
我追蹤了兩年的角色轉移：執行 → 編排 → 工具設計。

Custom Skills 是第三步，已經來到畫布上了。你不再只是 Figma AI 的使用者——你在編寫你的團隊所使用的 AI。

你每週重複做 10 次的工作流程是什麼？那就是你的第一個 skill。
