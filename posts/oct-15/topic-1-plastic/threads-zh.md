# Threads 貼文 — Plastic（繁體中文）

---

**長文版：**

設計檔案是介面的圖片。

這是我們行業中每一個工具都建立在其上的假設。你在 Figma 裡畫圖。你交出圖紙。工程師用 HTML、CSS、React——不管實際媒介是什麼——重建它。設計是一份規格書，不是事物本身。

Plastic 是一個在根本層面拒絕這個假設的設計工具。畫布就是 HTML 和 CSS。當你畫一個 frame、加上 auto layout、套用 token——你正在創建的就是真實的介面。你儲存的檔案是可以直接部署的網頁。

交接模式崩解了。工程師和編碼 agent 不需要從一個需要被解讀的截圖出發。他們從真實來源出發。

對 AI agent 來說：Claude Code、Codex、Cursor 和 Grok 透過 MCP 連接。它們讀取真實的設計結構，並在你觀看時即時在畫布上做出改變。每一步都可以 undo。Agent 正在觸及的 layer 會即時高亮顯示。關鍵的約束：agent 可以讀取程式碼來複製外觀，但無法編輯檔案或執行系統指令。它們只能透過 Plastic 自己的工具運作。這是正確應用的 constraint 架構——限制本身就是讓 agent 參與在生產環境中安全的東西。

這是一個我今年一直在觀察的模式。九月的 Elyx：一種人類可讀、AI 友善、可在 Git 中版本控制的新設計檔案格式——設計檔案即 constraint 文件。十月的 Timeful：一個畫布編輯直接寫入 .vue 檔案、程式碼編輯即時更新畫布的視覺 IDE。現在是 Plastic：HTML 和 CSS 作為設計媒介，任何步驟都沒有轉換。

三個工具。三個角度面對同一個根本問題：二進制設計檔案格式是 AI agent 需要讀取和編輯設計的工作流程的正確基礎嗎？

Constraint stack 時代——AGENTS.md、CLAUDE.md、design.md——假設二進制格式是固定的，並在其上建立橋梁。這些工具押注格式本身就是問題。如果其中任何一個獲得牽引力，橋接時代看起來就像一個過渡性的權宜之計，而不是永久解決方案。

**短版直接看法：**

二進制設計檔案格式的假設正在從三個方向同時被挑戰。

Elyx 押注新格式。Timeful 押注 Vue 的畫布即程式碼。Plastic 押注畫布即 HTML。

設計到程式碼的落差不是 Plastic 填補的東西。在這個模型中它根本不存在。

useplastic.app——僅限邀請的預覽版，Apple Silicon Mac 應用程式 + 瀏覽器。
