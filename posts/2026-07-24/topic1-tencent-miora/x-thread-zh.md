# X Thread — 騰訊 Miora（繁體中文）
**主題：** 騰訊 Miora 正式公開——完整的 AI 創意 agent 平台
**角度：** 「當 AI 有了製作團隊，設計師的工作變成創意總監，不是在 prompt」
**日期：** 2026 年 7 月 24 日

---

**Tweet 1（Hook）**
騰訊把 Miora 向全公眾開放了。

到處說它是「適合所有人的 AI 創作助手」。

我覺得這個框架說小了。

🧵

---

**Tweet 2**
Miora 不是一個 AI 在做所有事。

它是個 orchestration layer，根據你的目標，把任務分配給不同的專門 agent：品牌視覺、3D、影片、UI。

你說目標，Miora 拆解 brief，分配對的專才。

---

**Tweet 3**
舉個例子：

描述一個產品上市活動 →
→ 品牌視覺 agent 做海報
→ 3D agent 建產品渲染圖
→ 影片 agent 寫腳本、生成廣告
→ UI agent 組出 app 畫面

同一個對話。一致的視覺系統。不用為每個工具重新 prompt。

---

**Tweet 4**
讓這件事成立的關鍵是記憶層。

Miora 跨 session 記住你的品牌意圖——風格、語調、視覺方向。不會每次歸零。

這不是「有記憶的創作工具」，是「有機構記憶的創作團隊」。

---

**Tweet 5**
這改變了「指揮 AI」的意義。

一個 AI 輸出一個東西，你在 prompt。
多 agent 系統跑完整流水線，你在 direct：定義 brief、設定限制、review checkpoint。

執行者 → orchestrator 的轉移——但現在是製作公司的規格。

---

**Tweet 6**
8 個內建 skill（品牌視覺、影片、電商、互動遊戲）不是功能清單。

它們是 constraint architecture。每一個都框住了特定 brief 類型裡 agent 能做什麼。

你的工作：在 agent 開始之前，選對框架。

---

**Tweet 7**
說實話的部分：

多 agent 系統的錯誤是靜默累積的。一個 agent 的 output 是下一個 agent 的 input，小錯誤會疊加。

品質門檻不是看你生成什麼，是看你在流程裡設計了哪些 review gate。

---

**Tweet 8**
資深觀點：

「創意總監」以前是個理想頭銜。

現在是操作角色。

AI 協調各領域專才的時候，你的工作是：定 brief、設限制、出門前 review。

這個角色不會被自動化。而且 Miora 讓它更必要了。
