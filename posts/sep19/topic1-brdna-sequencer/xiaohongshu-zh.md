## Sep 19, 2026 | 圖片：topic1-xiaohongshu-zh.png（3:4）

---

**標題：** 你的品牌守則對 AI agent 沒有用。R/GA 做了什麼來解決這個問題？

---

品牌 PDF？AI agent 沒辦法行動。
Figma 檔案？還是太視覺化了。
Design token？越來越接近——但還不是完整的圖像。

R/GA 剛發布了 BRDNA Sequencer：把你品牌完整的 design system——元件、pattern、文案聲音、視覺規則——轉換成結構化 context，讓 Claude Code 這樣的 coding agent 可以在裡面真正運作。

Mailchimp 用了。他們的內部團隊現在可以 prompt Claude Code 來創作符合品牌的內容，不需要逐一對照品牌守則檢查輸出。

---

**為什麼資深 UX 設計師需要在意這件事：**

「AI 輸出沒有品牌感」的問題不是模型問題。是 design system 清晰度問題。

這是我從七月開始追的 pattern：
1️⃣ **v0 API** — design system 作為 API 參數
2️⃣ **OUI-1** — 元件庫作為模型訓練資料
3️⃣ **GeekLego / Astryx** — DS 規則在生成時就 baked in
4️⃣ **BRDNA Sequencer** — 完整品牌 DNA 作為 agent 的操作 context

每一個都把同一個概念往上推一層：你的 design system 是 AI 的品質上限。不是模型。

---

**BRDNA Sequencer 真正觸發的 audit：**

1️⃣ 你的 design token 是語意命名的，還是只對建立它的人有意義？
2️⃣ 你的元件規則有說明「為什麼」，還是只說「是什麼」？
3️⃣ Override 和歷史遺留例外有附上原因的文件嗎？
4️⃣ 你的文案聲音指南夠具體讓 agent 一致地應用嗎？
5️⃣ 一個從沒做過你品牌的人，能只靠你的 DS 文件就正確行動嗎？

---

**老實說：**

BRDNA Sequencer 不是可以自己設定的 SaaS 工具。是由 R/GA 和 Addition 幫你導入的。大多數團隊明天沒辦法直接買。

但概念驗證的訊號很清楚：在生產規模下，把品牌 DNA 結構化成機器可讀的 context 真的可行。

這表示你下一個 DesignOps 專案不是「把 AI 加進我們的流程」。而是「讓我們的 design system 清晰到足以讓 agent 使用」。

---

**資深 UX 的視角：**

能把 design system 翻譯成 agent context 的代理商有護城河。
投資 DS 清晰度的設計團隊有護城河。

AI 在這裡不是差異化因素。
你已經文件化的東西的品質，才是。
