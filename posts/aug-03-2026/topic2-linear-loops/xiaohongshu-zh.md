**標題：** Linear Loops：2026 年我見過最好的 agent UX 設計

**內文：**

Linear 推出了重複性的 AI agent 工作流程。但真正的故事是他們怎麼為信任感設計的。

**Loops 是什麼：**
① 用自然語言定義重複性任務
② 設定觸發條件：排程或事件
③ Linear Agent 自主執行，有完整 workspace context
④ 每次執行都被記錄、有時間戳記，任何隊員都能讀

**為什麼設計很厲害——四個 UX 決策：**

1/ 每個 Loop 是團隊共有的操作物件（不是消失的 prompt）

2/ 權限用後果描述：「這個 loop 可以建立 issue、更新規格、分配工作」——你在發布前就看到影響範圍

3/ Publish 閘門：修改都是草稿，明確發布才生效——不可能不小心把修改中的指令推到線上

4/ 執行歷史 = master-detail 稽核介面：選任一時間點的執行，讀到 agent 當時看到什麼、用了什麼 context、改了什麼

**給所有 agent 產品的測試：**
「不在場的隊員能打開這個自動化，解釋為什麼它跑、它碰了什麼、它改了什麼嗎？」

不能 → 你推出了沒有問責機制的自主性
能 → 這就是用 UI 解決的 agent trust

**給正在設計 agent 產品的設計師：**
先設計稽核流程，再設計功能本身。
Agent 行動的可信賴程度，取決於你的執行歷史有多好讀。

Permission model 永遠比 capability model 重要。
