# Threads Post — EN
## Topic: Linear Loops — Recurring Agent Workflows
## Date: Aug 3, 2026

---

Linear Loops just reframed what agentic UX should look like.

The feature lets you define recurring agent workflows — triage incoming issues, update project specs, coordinate cross-platform work — in plain language with a schedule or event trigger.

Every other "AI automation" feature treats the agent as a black box. You set it, it runs, something changes, and you trust that it did the right thing.

Linear's approach is different. Every Loop is a team-owned operating object with:
- A trigger and instructions (what it's meant to do)
- Permission rows (what it can touch, described by consequence not capability)
- A publish gate (edits are drafts until you explicitly go live)
- A run history (master-detail: every run, every action, every issue touched)

The run history is the UX I want every agentic product to copy. When I come back from a weekend and an agent has been running, I can open the Loop, select a run by timestamp, and read exactly what it saw, what context it used, and what it changed.

That's what agent trust looks like — not a settings panel, not a confidence score. An inspectable record of what happened.

The test I'd give every agentic product: can a teammate who wasn't there open the automation and explain why it ran, what it was allowed to touch, and what it changed?

If no → you've shipped autonomy without accountability.
If yes → that's agent trust, solved with UI design.
