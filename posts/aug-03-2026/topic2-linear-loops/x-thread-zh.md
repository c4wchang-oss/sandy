# X Thread — 中文（繁體）
## 主題：Linear Loops — 重複性 Agent 工作流程
## 日期：2026 年 8 月 3 日

---

**推文 1/8**
Linear 剛推出了我見過設計得最好的 agent 自動化 UX。

不是因為它能做什麼，而是因為它在執行後讓你看到什麼。

---

**推文 2/8**
功能叫 Loops。

用自然語言定義一個重複性任務，設定觸發條件（排程或事件），然後 Linear Agent 就自主執行——跨你整個 workspace，能存取所有 issue、專案和連接的工具。

---

**推文 3/8**
跟其他「AI 自動化」功能最大的不同：每個 Loop 是一個可以被檢視的操作物件。

不是消失的 prompt，而是一個有觸發條件、指令、權限範圍和執行歷史的團隊資產，任何隊員都能讀。

---

**推文 4/8**
執行歷史的 UI 是我最想研究的部分。

左邊是依日期時間排列的執行清單，右邊的 master-detail panel 顯示：agent 看到了什麼、用了什麼 context、採取了什麼行動、碰了哪些 issue。每次執行後都有，包括你睡著的時候。

---

**推文 5/8**
這解決了 agent 產品裡最難的設計問題。

不是「agent 能不能做到那件事」——那個每個月都在變容易。難題是：「我回來發現事情變了，能理解為什麼嗎？」Linear 用一個畫面回答了這個問題。

---

**推文 6/8**
Publish 閘門是另一個聰明的 UX 決策。

修改中的 loop 存成草稿，只有明確按下 Publish 才上線。你不可能不小心把修改中的指令推到正在執行的自動化上。自主性 + 確認步驟。

---

**推文 7/8**
權限用後果描述，不用技術能力。

不是「agent 可以使用 GitHub tool」，而是「這個 loop 可以建立 issue、更新規格、將工作分配給團隊成員」。你在發布前就看到影響範圍。

---

**推文 8/8**
真正的標題：Linear 不是推出了一個「設完不管」的自動化功能。

它推出了一個以稽核為先的 AI agent 運作模型。

測試標準：不在場的隊員打開這個 loop，能解釋剛才發生了什麼嗎？能的話，agent trust 的問題就解決了。
