## 主題：Linear Loops — 重複性 Agent 工作流程
## 日期：2026 年 8 月 3 日

---

Linear Loops 重新定義了 agent 產品的 UX 應該長什麼樣子。

這個功能讓你用自然語言定義重複性的 agent 工作流程——排程或事件觸發，Linear Agent 就去執行：分類 issue、更新專案規格、協調跨平台工作。

我見過的其他「AI 自動化」功能幾乎都把 agent 當成黑盒子。你設好它，它跑，某些事情改變了，然後你只能相信它做了正確的事。

Linear 的做法不一樣。每個 Loop 是團隊共有的操作物件，包含：
- 觸發條件和指令（它被設計來做什麼）
- 權限列（它能碰什麼，用後果而非技術能力來描述）
- Publish 閘門（修改是草稿，到你明確發布才生效）
- 執行歷史（master-detail：每次執行、每個行動、每個被碰到的 issue）

執行歷史的 UI 是我最希望所有 agent 產品都能學習的設計。週末回來，agent 一直在跑，我打開 Loop，選一個執行時間點，就能讀到它當時看到了什麼、用了什麼 context、改了什麼東西。

這才是 agent trust 的真正長相——不是設定面板，不是信心分數，而是一份可以被閱讀的行動紀錄。

給所有 agent 產品的測試：不在場的隊員能打開這個自動化，解釋為什麼它跑、它被允許碰什麼、它改了什麼嗎？

不能 → 你推出了沒有問責機制的自主性
能 → 這就是用 UI 解決的 agent trust
