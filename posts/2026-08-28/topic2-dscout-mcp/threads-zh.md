# Threads 貼文 — 繁體中文
## 主題：Dscout MCP — 研究嵌入 AI 工作流

---

**長文：**

Dscout 這週推出了 MCP。在 Claude 或 Figma Make 裡面，你現在可以草稿一個 study、發布給參與者、拿回結果——不用打開 Dscout 的應用程式。

這件事的標題版本是「更快的研究」。這樣說低估了它。

真正改變的是距離感。研究過去是一個獨立的流程——專門的工具、專門的人、專門的時程。MCP 把這個距離壓縮了。研究變成你在設計功能或寫程式的同一個工作流程裡做的事。

這是結構性的轉變，不是加速。

同樣的模式一直在重複：ProtoPie MCP、Dovetail Channels、Usertour MCP，現在是 Dscout。每一個研究接觸點都在變成 agent endpoint。問題從「我們什麼時候可以排得進研究？」變成「我們現在需要 AI 回答什麼問題？」

風險是顯而易見的。Brief 的品質還是天花板。「我們負擔得起做這個 study 嗎？」以前是一道關卡。這道關卡基本上消失了。「我們問了對的問題嗎？」是唯一剩下的問題——而且它比聽起來難得多。

我一直回到同樣的重新定框：AI 嵌入研究讓你非常容易快速得到聽起來有把握的答案，但問的是錯誤的問題。失效模式不是「沒有做研究」，而是「研究做起來很便宜所以我們沒有好好思考它」。那比沒做研究更糟。它看起來像證據，但不是。

Senior researcher 的角色沒有消失。但交付物改變了。你不是在跑 study 和寫報告。你是在設計研究系統——問題架構、study 排序、合成標準——然後 agent 去執行。這是更難的工作。需要更多判斷力，不是更少。

---

**簡短核心觀點（放在 Threads 最前面）：**

Dscout 剛推出了 MCP。你現在可以在 Claude 裡面跑 user research，不用切換工具。

瓶頸移動了。不再是「我們負擔得起做這個 study 嗎？」而是「我們寫了對的 brief 嗎？」

聽起來是個小變化。不是的。
