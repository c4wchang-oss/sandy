今天發生了一件我覺得被低估的事。

OpenAI 的 GPT-6 Intelligent UI 正在向所有人推出——Free 和 Go 方案從今天開始。報導把它描述成「更豐富的聊天回應」，技術上是準確的。但更精確的框架是：ChatGPT 現在會根據你的問題決定要給你什麼樣的介面。不是模型填入欄位的更豐富模板。模型在選擇格式。

問自行車的構造：有可點擊部位的互動示意圖。計畫食譜：一個可以調整人數、份量自動更新的即時 widget。分帳：它在對話中直接建出計算器。解釋複雜主題：並排比較，或是你可以逐步探索的互動示意圖。只需要簡單答案：純文字。

這是推論時的 UI 組合。底層是一個原生可串流的元件函式庫，以及一個在 GPT-6 繼續思考時逐步渲染介面的編譯器。模型從問題 context 中學到何時生成互動視覺以及如何格式化它們。

我一直在追蹤 AI 工具如何在升級的規模接管 IA 決策。八月的 ChatGPT Visualize 讓模型從資料問題決定你的圖表類型。十月的 Basedash 讓模型從一句話結構出整個產品 dashboard IA。今天的更新讓模型在對話層面本身決定你的回應格式。同一個底層問題，不同的規模。

失敗模式在每個規模都一樣：自信、精緻、錯誤的 IA。當模型帶著視覺權威感和流暢度呈現它的格式選擇時，大多數用戶會調整心智模型去匹配呈現，而不是質疑格式選擇本身。這不是假設性的——有合理的證據顯示這在視覺化層面確實發生，我預期在對話層面也會發生。

UX 從業者的角色轉變：在對話層面，我們不再是組合介面——模型在做。我們的角色移動到評估生成的介面是否真的服務用戶的真正目標。這意味著培養辨識「精心製作但實際上在誤導用戶的 AI 組合介面」的能力，然後清晰地表達為什麼，清晰到足以採取行動。這不是更小的技能。它更難教、更難練習、更難在作品集裡展示。

誠實的說明：「豐富的聊天回應」之前就嘗試過了——Slack Canvas、Teams 整合的分頁視圖、各種聊天機器人 widget 實驗。Intelligent UI 真正不同的地方是格式選擇發生於問題語義，而不是寫死的規則。組合智能，不是更豐富的模板。這在實踐中是否對用戶真的更好，是沒有人用嚴謹方式回答過的實驗性問題。

我一直思考的研究問題：當 AI 自信地選擇了錯誤的回應格式——不是令人困惑地錯，而是精緻地錯——用戶會發現並糾正嗎？還是他們會重組理解去配合被給予的東西？在對話規模，這個問題非常重要。我沒有看到任何人現在在設計這個研究。
