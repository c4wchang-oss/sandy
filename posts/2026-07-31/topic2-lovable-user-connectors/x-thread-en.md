**Tweet 3:**
With app user connectors: each user connects their own account.

**Tweet 4:**
The UX implication most people are missing:
You're no longer designing for a fixed dataset.
You're designing for N personal data realities.
Your empty states, loading states, error states now need to work across contexts you cannot predict.

---

**Tweet 5:**
This is constraint architecture at the user level.
The designer doesn't decide what data appears — the user's own permissions do.
A hiring manager sees their Workday pipeline. A sales rep sees their CRM.
Your layout has to hold across all of it.

---

**Tweet 6:**
Auth architecture that used to be an engineer's problem is now a design consideration.
What happens when a user hasn't connected yet? When their token expires? When they have read-only access?
These aren't edge cases. They're the primary flow for a percentage of users.

**Tweet 7:**
Honest note: this expands who can build what, but it shifts responsibility.
The product you ship is now a framework that runs on your users' real data.

Systems thinking isn't optional here.
