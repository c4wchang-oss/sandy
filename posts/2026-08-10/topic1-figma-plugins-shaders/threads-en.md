# Threads Post — Figma Generative Plugins + Shaders (English)
**Date:** 2026-08-10
**Format:** Long-form personal reflection, no hashtags

---

Hot take: the most underappreciated feature in Figma's generative plugins launch isn't the shaders — it's the distinction Figma quietly drew between plugins and the agent.

Plugins are for deterministic work. Same input, same output. You define the tool once and it runs without judgment every time.

The agent is for adaptive work. It brings context, reads your file, makes calls you didn't specify.

This split matters more than it looks. Most teams I've spoken to treat AI tools as a black box they talk to. They re-prompt the agent to rename layers, apply spacing, strip overrides — every single time. That's not using AI well. That's using AI expensively.

The move is: identify the repeatable stuff in your workflow. Document it. Then ask the Figma agent to build a plugin for it. Free in beta. Doesn't consume credits to run — ever.

The shaders piece is genuinely exciting too. GPU-rendered visual effects from natural language, parameterized as native Figma properties. Your design system can now include a "holographic glitch fill" or a "low-frequency noise overlay" that any teammate can apply. No shader code knowledge required.

But honest note: shaders are only as good as your prompt specificity. This isn't a magic wand — it's a translation challenge. "Make it look cinematic" will get you something generic. Describing the exact visual physics will get you something usable.

The bigger arc I'm watching: Figma is becoming an environment where you design the tools you use. That's a meaningful shift. It means the senior designer skill set is expanding from "what to make" to "what tools to build to make it faster next time."
