## 🐦 X (Twitter) — 推文串 #1
### 主題：Figma Design Agent（Config 2026）

**第 1 則 — 開場**
> 用了兩週 Figma Design Agent，說說我這個資深 UX Designer 的真實感受。
>
> 不是業配，不是炒作，是真的拿來工作之後的想法 🧵

---

**第 2 則 — 破除迷思**
> 外面在說的：「AI 要取代設計師了！」
>
> 我的實際感受：Figma Agent 更像一個超快、但仍然需要你指導的初級設計師——它了解你的 component library，但不知道為什麼這樣做。
>
> 你還是主導。你還是決定。你還是對結果負責。
> 這不是限制，這就是設計工作的本質。

---

**第 3 則 — 真正好用的地方**
> Agent 做得很好的事：
>
> → 批量更新整個 library 的 component 描述
> → 一鍵把 40 個 frame 轉成 dark mode
> → 統一命名規則（那個你一直說要修但沒修的）
> → 替換整個 flow 的 placeholder 文字
>
> 這些事以前吃掉我 40% 的工作時間。現在沒了。

---

**第 4 則 — 真正的重磅功能**
> MCP 連接器才是這次最被低估的功能。
>
> 我把 Figma 接了 Notion 的 PRD 和 Linear 的 ticket。
> 現在 agent 在設計的同時，可以直接參考產品需求。
>
> 第一次感覺「設計稿」和「需求文件」住在同一個地方。
> 和 PM 的 handoff 摩擦，明顯少了。

---

**第 5 則 — 誠實說限制**
> Agent 目前做不到的事：
>
> → 在三個都合理的 layout 方案中，選出「感覺對的那個」
> → 理解一個互動模式在技術上 OK，但對你的用戶來說感覺不對
> → 知道什麼重要、什麼不重要
>
> 設計判斷不是 prompt。是十年的模式識別。
> 這塊還是我們的。

---

**第 6 則 — 辣的觀點**
> 熱觀點：2026 年最吃香的設計師，不是 prompt 寫得最快的。
>
> 是那些把 design system 建得最清楚、token 最嚴謹、component 文件最完整的人。
>
> AI 品質 = 你的設計系統品質。
> Garbage in, garbage out——只是現在快很多。

---

**第 7 則 — 心態轉換**
> 給每一個感受到壓力的資深設計師：
>
> 你的工作正在從「執行」轉向「指揮」。
> 從「做」轉向「決定要做什麼」。
>
> 這不是威脅。這是我們要求了多年的升級。
> 問題是：你有沒有在建構讓 AI 放大你的系統？

---

**第 8 則 — 行動呼籲**
> 現在最值得投資的不是學提示詞技巧。
>
> 是：
> • 整理你的 design tokens
> • 把 component library 的文件補完
> • 讓團隊對命名規則達成共識
>
> 這些是你的 AI 工作流的「訓練資料」。
> 把基礎建好，Agent 才能幫你飛。

## 🐦 X (Twitter) — 推文串 #2
### 主題：「Vibe Coding」時代結束了，真正的考驗來了

**第 1 則**
> 「Vibe Coding」這個詞快要過時了。
>
> 2026 年，我看到在掙扎的設計師都在拼命刷 prompt。
> 活得很好的那群人？他們在建更嚴謹的約束架構。
>
> 說說這兩者的差異 🧵

---

**第 2 則**
> Vibe Coding（2024）：
> 說一說 → AI 生出來 → 上線 → 修爛掉的東西
>
> Agentic Engineering（2026）：
> 先定義約束 → 鎖定 token → 設計規則 → 品質把關 → 再讓 AI 執行
>
> 工具一樣，心態完全不同。

---

**第 3 則**
> 現在資深設計師在讓 AI 動手之前，會先定義：
>
> 1. Token 系統（間距、顏色、字型——鎖定）
> 2. Accessibility 規則（非談判項目）
> 3. 邊界案例（壞掉時應該怎麼壞）
> 4. 品牌行為原則（不是只有視覺手冊）
>
> 這才是 AI 真的聽得懂的「簡報」。

---

**第 4 則**
> GPT-5.6 進 Figma Make 了，從設計稿生成的第一版保真度真的很令人驚訝。
>
> Layout 保留。層次保留。間距保留。
>
> 「AI 原型」和「真實產品」之間的差距在縮小。
> 你的工作不是阻止它，是引導它。

---

**第 5 則**
> Cursor 3.7 的 Design Mode 讓我在 demo 時讓 PM 以為在看魔術：
>
> 直接在瀏覽器裡點 UI 元素、語音說要改什麼、AI 即時更新。
>
> 我們不是在寫程式。我們是在像電影導演指導演員一樣，指導 AI。

## 🧵 Threads 長文 #1
### 主題：Figma Design Agent 兩週真實使用心得

用了兩週 Figma Design Agent，給大家一個資深設計師（10 年+）的真實 review。

---

先說背景：Figma 在 Config 2026 發佈了 Design Agent——直接住在 canvas 上，連接你的 component library，還能透過 MCP 連接器接上 Notion、Slack、Linear 等外部工具。

聽起來很厲害。確實有點厲害。但原因跟你想的可能不一樣。

---

**最先改變我工作流的東西：**

第一件事就是接 MCP。把我們的 Notion PRD、用研摘要、產品需求丟進去。

現在在 Figma 設計的同時，Agent 有了真實的產品背景。「需求文件」和「設計稿」第一次住在同一個空間。光是這一點，就省了我每週大量的來回確認。

---

**真正的超能力（沒什麼人在講）：**

不是生成新的畫面。是幫我消滅那些偷走創作能量的設計雜務。

批量改 layer 名稱。更新整個 library 的 component 描述。把 60 個 screen 轉 dark mode。統一命名規則。

這些以前佔了我 30-40% 的工作時間。Agent 現在大部分都能處理。那些時間回到了真正的思考上。

---

**我會告訴團隊的殘忍事實：**

AI Agent 的智慧上限 = 它工作所在的 design system 的品質。

如果你的 token 不一致、component 沒文件、命名靠緣分——Agent 只會幫你更快速地生產那些混亂。

現在最值得投資的不是學提示詞。是建一個值得被放大的設計系統。

---

**Agent 真的做不到的事：**

在三個都合理的 layout 方案中，選出最符合品牌情感定位的那個。理解一個互動模式技術上沒問題，但對你的使用者感覺很彆扭。決定什麼重要、什麼不重要。

那還是設計。那還是我們的事。

---

**給資深設計師的話：**

不要問「AI 會不會搶我工作？」

要問「我如何把我的工作架構設計得讓 AI 可以放大它？」

現在最積極在建清晰系統、嚴謹約束、周全文件的設計師——他們不是被這波浪潮威脅的人。

他們是被浪潮帶起來的人。

## 🧵 Threads 短文 #2
### 主題：「Vibe Coding」時代結束了

「Vibe Coding」的時代正式結束了。取而代之的東西更有意思。

2026 年的資深設計師不是在拼命刷 prompt——是在把約束架構建得更嚴謹。先鎖定規則，再讓 AI 執行。輸出品質的差異，不誇張。

工具都一樣：Figma、Cursor、Claude、v0。但心態已經從「生成再看看」徹底轉向「約束、指導、品質把關」。

Figma 的 Design Agent。GPT-5.6 進了 Figma Make。Cursor 的 Design Mode。Claude Code + Figma MCP 雙向設計↔程式循環。

這些工具沒有在取代設計流程。它們在篩選：哪些設計師有真正的設計流程，哪些只是習慣。

你是哪一個？
