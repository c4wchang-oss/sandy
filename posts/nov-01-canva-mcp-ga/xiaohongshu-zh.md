## 標題
Canva MCP 開放自助 GA——個人帳號認證模式才是你的設計團隊要讀的治理故事

---

## 正文

Canva 的遠端 MCP server 現在對所有開發者開放，不需要等待名單。在 Developer Portal 設定一個 OAuth app，你的用戶就可以把自己的 Canva 帳號連接到任何 AI 工具。

以下是你實際上可以做什麼——以及個人帳號認證模式對設計團隊意味著什麼：

**從 Claude 或 Cursor 現在可以做到的：**

1. **從 brief 生成設計** — 描述你需要什麼，Canva 幫你做出來。不需要開 Canva，使用帳號裡現有的品牌 template 和資產。

2. **搜索現有作品** — 在 AI 工具裡搜索設計、資料夾、頁面。先找到現有的，再決定要不要生成新的。

3. **精確編輯** — 描述要改的地方，Canva 在現有設計上直接修改。不用手動打開編輯器。

4. **以任何格式匯出** — PDF、PNG、PPTX、MP4，直接從 AI 工作流程匯出，不用碰 Canva。

**對個人設計師和小型工作室：**
純粹的好消息。你的帳號、你的 AI、你的工作流程，最少的摩擦，最大的彈性。

**對大型團隊的品牌負責人和設計系統 owner：**
這部分值得仔細讀。

純個人帳號認證，沒有組織層級驗證，沒有服務帳號。每個設計師連接自己的 Canva 帳號，MCP 尊重他們個人方案的權限——不強制執行跨團隊的品牌 template 治理。

- 如果你的品牌治理靠流程（共享 library、Notion 文件、Slack 提醒）：個人帳號 MCP 存取會繞過它。
- 如果你的品牌治理靠架構（管控的 template 存取、鎖定的主檔案）：你沒問題。

**對比 Figma 的模型：**
Figma MCP = 企業管理授權、基於角色的席位、受管控的目錄。靠架構的治理。
Canva MCP = 個人 OAuth。靠個人判斷的治理。

兩個都是誠實、刻意的選擇，不分對錯，為不同的組織成熟度設計的。

**Senior UX 的解讀：**
從 AI 工具到 Canva 設計生產的通道現在打開了。問題是你的品牌約束，有沒有設計好——在每個人都有自己的 AI → Canva 生產線的世界裡。如果沒有，先設計治理層，再讓團隊連接。
