**Title:**
GPT-6.1 Terra: what cheap computer use means for design work

---

**Body:**

GPT-6.1 Terra (Oct 26) = visual reasoning + computer use + writing in one model. 3x faster than GPT-6 Astra, 50% lower API cost than GPT-5.6 Terra. Available in ChatGPT Work and Codex.

This isn't just a faster model. It's the efficiency point where AI-assisted design QA becomes routinely practical.

---

**What It Can Actually Do:**

① Visual reasoning: read product photos, campaign layouts, architectural drawings
② Computer use: click through apps, browsers, and interfaces on macOS + Windows
③ Writing: specs, summaries, structured output — results-first style

---

**The Design QA Use Cases:**

① Check campaign assets for cropping and text placement issues
② Match product photos to catalog entries and update listings
③ Click through a prototype to verify interactive state behavior
④ Flag mismatches between design token values and rendered UI output

---

**Why 3x Faster + 50% Cheaper Actually Matters:**

When cost drops:
- Running these checks daily becomes economically defensible
- The bottleneck shifts from cost → to brief quality
- Senior designer's job: write a precise brief, not manually do the check

---

**The Accessibility Connection (important):**

When agents use your product's UI routinely:
- Keyboard shortcuts = agent speed
- Focus rings = agent navigation
- ARIA labels = agent context
- Missing any of them = agent errors

Accessibility isn't just compliance. It's your agent's usability floor.

---

**Setup:**

① ChatGPT desktop app → switch to Work mode
② Install Computer Use plugin
③ macOS: grant Screen Recording + Accessibility permissions
④ Windows: keep target app visible in active desktop
⑤ Select GPT-6.1 Terra from model list in Advanced

---

**Honest Limits:**

⚠️ Not in Chat — Work and Codex only
⚠️ UAE inference residency not supported
⚠️ Visual QA still needs precise briefs — Terra executes, not interprets ambiguity
⚠️ "Check if it looks good" = not a brief. "Check if text is cropped, CTA visible at mobile, hex matches spec" = a brief

---

**Senior Designer Take:**

The question is no longer "can AI check this?"

It's "is my brief precise enough for it to check correctly?"

Brief quality is now the cost floor and quality ceiling for AI-assisted design QA. That's a DesignOps governance question before it's a tool question.
