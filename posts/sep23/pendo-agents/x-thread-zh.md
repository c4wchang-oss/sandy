**Tweet 2**
Pendo 昨天推出了「Pendo for Agents」。

兩個部分：Agent Analytics（正式版）+ Agent Toolkit（公開測試版）。

Agent Analytics 回答：這個 agent 真的在幫助用戶嗎？
Agent Toolkit 回答：為什麼沒有，怎麼解決——在用戶打字之前就開始。

---

**Tweet 3**
Agent Toolkit 透過 MCP 把任何 AI agent 連接到 Pendo 的行為數據。

Agent 能即時取得什麼：
— Session 情境：用戶剛才試著做什麼
— 挫敗觸發：憤怒點擊、死點、U 型折返、錯誤點擊
— 流程提醒：有人在某個定義好的流程中途離開的位置
— 導引浮現：解決他們問題的那個確切說明

這些是我們收集了十年的訊號。現在它們是 agent 的輸入。

---

**Tweet 4**
有個值得注意的 UX 框架：

「Agent 通過了評估檢查，但如果不知道用戶想要達成什麼，就沒有真正在幫助。」

這正是 UX 從業者對「任務完成率」作為易用性指標的批評——說了 25 年了。

基準分數 ≠ 用戶成功。

---

**Tweet 5**
設計上的影響比表面看起來更深。

你的 AI agent 繼承了你產品的行為情境。這代表：

— 你從未修復的每個不完整流程 = agent 會錯誤回應的流程提醒
— 用戶憤怒點擊過去的每個死胡同 = agent 現在要回應的挫敗訊號
— 沒有人完成的每個 onboarding 步驟 = agent 馬上會發現的空缺

你的 UX 債務現在直接反映在 agent 的有用程度上。

---

**Tweet 6**
MCP 的模式正在成為行為數據的基礎設施，不只是設計工具。

八月有 Dscout MCP。八月有 Dovetail Channels。九月有 Attest MCP。現在有 Pendo 的 session 情境 MCP。

這個弧線：研究數據 → 產品分析 → 即時行為訊號，全都流入 agent 情境。

Agent 不是取代產品的。它在讀取產品的行為歷史。

---

**Tweet 7**
誠實的注意事項：

Agent Analytics 是正式版。Agent Toolkit 是公開測試版——挫敗訊號和流程提醒需要獨立的主動支援連接，而且在測試期間需要聯繫 Pendo 支援才能開啟。

另外：Pendo 自己的 Leo agent 用這個方法提升了 61%。這是一個數據點，不是基準。但方向性值得注意。

**Tweet 8（CTA）**
「Agent 通過評估但使用者感覺沒被幫到」一直都是情境問題。

情境是：這個用戶剛才試著做什麼？他們卡在哪裡？哪份說明已經回答了這個問題？

那個情境一直都存在於你的分析資料裡。問題是你的 agent 能不能讀到它。

這是現在的設計問題。
