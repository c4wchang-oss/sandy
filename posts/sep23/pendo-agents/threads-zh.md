Pendo for Agents 的公告裡有一個發現讓我一直在想：在 4,700 萬次 agent 對話之後，反覆出現的回饋不是「模型搞錯了」。而是「agent 通過了評估，但如果不知道用戶想要達成什麼，就沒有真正在幫助。」

這不是 AI 問題。這是情境問題。而且這跟 UX 從業者幾十年來對「任務完成率」作為易用性指標的批評如出一轍。你可以通過測試，但還是沒幫到人。

Pendo for Agents 昨天推出。兩個部分：Agent Analytics（已正式版）和 Agent Toolkit（公開測試版）。Agent Analytics 衡量 agent 是否在幫助用戶。Agent Toolkit 試著修正為什麼沒有——透過 MCP 把任何 AI agent 連接到 Pendo 的行為數據。即時的 session 情境。挫敗訊號：憤怒點擊、死點、U 型折返、錯誤點擊——直接送到 agent。針對中途放棄的流程提醒。針對用戶真正問題的說明文件浮現。

讓我印象深刻的是：我們收集這些訊號已經幾年了。熱力圖、session 錄影、漏斗分析、群組流失。這些從來都不是 agent 的即時情境。一直都是回顧性的報告，給可能在下個 sprint 採取行動的產品團隊看的。Pendo for Agents 是改變的時刻——產品分析團隊維護了十年的行為數據層，從回顧性的儀表板變成 agent 的即時輸入。

設計上的影響比表面看起來更深。你的 agent 繼承了你產品的行為歷史。這代表每一個不完整的 onboarding 流程、每一個用戶靠憤怒點擊硬撐過去的死胡同、每一個中途被放棄的工作流程步驟——這些現在是你的 agent 在用戶需要幫助的那一刻出錯的直接輸入。你的 UX 債務不再是抽象的了。它以 agent 失敗的形式即時出現。

資深 UX 在這裡的角色：你不再只是設計用戶點擊的界面。你在架構 agent 繼承的行為情境層。你的 IA 品質、你的流程、你的說明內容——那現在是你的 agent 能有多有用的天花板。

注意事項：Agent Toolkit 還是公開測試版。主動支援（挫敗訊號 + 流程提醒）需要獨立的連接，在測試期間需要透過 Pendo 支援才能開啟。Intercom Fin 有最流暢的整合；自訂 agent 也支援但需要更多設定。61% 提升的數字來自 Pendo 自己的 Leo agent——一個內部數據點，在更多資料發布之前值得保持懷疑。

但匯聚的訊號更難忽視。八月有 Dscout MCP。八月有 Dovetail Channels。九月有 Attest MCP。現在九月有 Pendo 的行為層。每一層的用戶研究和產品分析都在進入 agent 情境。這個模式很清楚：agent 在讀取產品的行為歷史。你的工作是確保那段歷史值得閱讀。
