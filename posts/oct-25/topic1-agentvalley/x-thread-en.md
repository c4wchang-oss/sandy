**Tweet 3**
Here's why this matters from a UX perspective.

When you have 5 agents running, the permission dialog becomes your most high-stakes notification.

"May I git push to main?"

That appears in a terminal tab. You're in a different window. You won't see it for 20 minutes.

The notch is where your eye already goes. That's where the signal should live.

---

**Tweet 4**
The interaction design is worth studying:

→ Red badge = one or more agents waiting
→ Click notch → see which one + what it's asking
→ Jump to exact terminal tab in one click
→ Optional plugin: approve or deny directly from the notch

The write-access part requires a plugin you install yourself. The read-only monitoring is the default, verifiable behavior. That's the correct split.

**Tweet 5**
This extends a pattern I covered three weeks ago: AI agent observability as a spatial UX design problem.

Cubicle (Oct 4): pixel-art office where each AI agent occupies a desk. Spatial visibility at a glance.

AgentValley (Oct 24): notch dashboard. Each agent, one card. Same design bet, smaller surface, closer to where your attention already is.

The log file is the wrong answer to "which agent needs me."

---

**Tweet 6**
Two trust architecture decisions I think are correct:

1. Core monitoring reads local Claude Code files + system processes only. No external requests. Open-source, so you can verify it.

2. Write access — approving commands from the notch — is opt-in via a plugin you install yourself. Monitoring layer and execution layer are intentionally separate.

Read-only as the default is a design decision, not a limitation.

AgentValley tracks per-project, per-session AI costs at API prices. Exportable as a PDF statement of work.

First tool that makes AI agent cost a per-project line item — not just a monthly bill you can't explain to a client.

Brief quality = credit efficiency. Now you can see it at the project level.
