每次新的圖像模型發布，我的動態就有人貼一張 UI mockup 截圖，然後寫「這對設計師來說改變了一切」。

兩週後他們失望了，因為 mockup 無法作為真正的介面使用，文字稍微有點錯，元件狀態從來就不存在，產品改變了卻什麼都不會更新。

Nano Banana 2.1 在 AI 圖像生成方面是真正的品質提升。Google 改善了標題級別的文字渲染、資訊圖表版面準確度、寬格式 tiling（1:4 和 4:1 比例的 banner 現在可以正常工作），以及多參考角色一致性。可設定的 thinking 等級——minimal、medium、high——是一個值得理解的新工作流程變數。Infographic Design 的 benchmark 是 1048，是我見過任何圖像模型被引用的最高分，對 UX 交付物工作是真實的訊號。

但我一直回頭看 model card。因為 Google 發布了一個，而且它是誠實的：1K 解析度下的小字還是模糊的，長段落還是渲染不好，左右空間推理還是偶爾混亂，角色一致性有改善但不保證。

這些確切的限制正是資訊圖表和 UI mockup 所依賴的。「更好的文字」是指更好的標題。不是圖表裡資料標籤上的細字。

我一直回頭想的區別：圖像模型 vs 設計模型。圖像模型產生高品質像素。設計模型——Linearity Vector 1.0、Vyb、Canva Craft，都在過去十天發布——產生可編輯的工作檔案、保持可編輯的活字、當東西改變時你可以更新的設計結構。Nano Banana 2.1 明顯是前者，這沒問題。只是意味著要知道分工。

圖像模型的領域：hero 視覺、寬格式 banner、插圖場景、利害關係人簡報中的視覺方向、研究文件中的短格式多語言標籤。

設計工具的領域：介面元件、元件狀態、品牌 token、互動邏輯、任何交接後需要更新的東西。

Grounding 功能對設計研究值得探索。連接到 Google Web 和 Image Search，模型可以不需要你提供就取用真實世界的視覺參考。對歷史參考生成、競品視覺研究、特定時代場景創建很有用。不是跳過版權或準確性查核的許可。但確實是不同的能力。

Nano Banana 2.1 是更好的圖像模型。把它用在圖像模型擅長的事上。「螢幕的圖像不是螢幕」還是適用的。
