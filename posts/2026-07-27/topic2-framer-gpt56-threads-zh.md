# Topic 2: Framer 3.0 + GPT 5.6 — Threads Post (Traditional Chinese)
**Date:** 2026-07-27
**Platform:** Threads
**Format:** Long-form personal reflection
**Angle:** 模型分配是創意方向決策，不是定價決策

---

Framer 剛推了效率更新：Credits 減少 25%，多步驟構建減少 60-67%，GPT 5.6 Terra 成為新的預設模型。

這個更新看起來像是一個定價調整的腳注。

不是的。

Framer 3.0 有三個 GPT 5.6 模型選項：Sol（最強創意品質，同 GPT 5.5 的 Credits 成本）、Terra（0.6x Credits，平衡）、Luna（0.4x Credits，速度快兩倍）。你選哪個模型跑哪個任務。這不是定價功能 — 這是創意方向決策。

我現在的模型分配邏輯：Sol 用在首屏版型探索，這是判斷門檻最高的創意工作，值得全額 Credits。Terra 用在一致性審查和響應式斷點，我需要的是系統性思維，不是創意探索。Luna 用在大量 CMS 更新和全站 find-and-replace，速度重要，品質已經由 design system 定義好了。

這跟管理一個團隊的邏輯一樣。你不會把最貴的創意資源放去寫每一行說明文字。問題是：你能不能把設計任務分類清楚，讓模型選擇有根據？

Framer 3.0 更大的故事是 External Agents。Claude Code 透過 Framer CLI 連進來，自動在 branch 上運作，用你自己的 LLM tokens — 不消耗 Framer Credits。Framer 變成了你 Claude Code pipeline 的一個部署目標。

這是一個架構性的轉變。設計工具不再是設計的起點。它是 AI 落地的地方。你在畫布上做審查。Agent 是作者。資深設計師的角色是管理 Branching 策略和模型分配政策 — 不是管滑鼠點哪裡。

如果你已經在用 Claude Code：試試 Framer 的 External Agents。如果你是純設計師：從 Terra 的一致性審查開始。最實用、最省 Credits 的切入點。
