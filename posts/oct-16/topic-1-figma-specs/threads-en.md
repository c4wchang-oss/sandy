# Threads Post — Figma Specs + Code Layers (EN)

---

Been thinking about what Figma's Specs launch actually changes.

On the surface it's a multiplayer Markdown editor that lives on the canvas. Teams can embed frames, diagrams, code layers inline. No screenshot links that go stale. Decisions and design artifacts in the same place.

The real shift: the spec is now the agent's brief.

Before today, handing off to a coding agent meant translating your designs into text and hoping the translation held. With Specs + Figma MCP: copy the spec link, paste it to a coding agent → it receives Markdown, frame references, Code Connect snippets, code layers. The structure of the design intent, not a text description of it.

Combined with Code Layers — interactive, code-backed prototypes on the Figma canvas that can be converted BACK into editable design layers — the design-code loop is finally closed inside a single tool. Not a handoff. A shared artifact with two representations.

For 10 years, the job was "make the handoff clearer." Today the handoff becomes the spec, and the spec is inside the file.

The quality of your Specs is now your quality ceiling with any coding agent. That makes spec-writing a DesignOps discipline, not an afterthought. The teams who figure this out in the next few months will have a structural advantage in AI-assisted development — not because they have better AI, but because they're giving it better input.

Honest note: Code Layers is free through November 4 on paid plans. That's your evaluation window before it becomes a credit conversation. Use it intentionally, not just to try it.
