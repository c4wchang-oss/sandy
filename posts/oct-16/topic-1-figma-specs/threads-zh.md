# Threads Post — Figma Specs + Code Layers（中文）

---

在想 Figma Specs 真正改變了什麼。

表面上它是一個住在 canvas 上的多人 Markdown 編輯器。團隊可以在行內嵌入 frames、diagrams、code layers。沒有過期的截圖連結。決策和設計 artifact 在同一個地方。

真正的轉變：Spec 現在是 agent 的 brief。

在這之前，把任務交給 coding agent 意味著把你的設計翻譯成文字，然後希望那個翻譯不會出錯。有了 Specs + Figma MCP：把 spec 連結貼給 coding agent，它收到的是 Markdown、frame 參考、Code Connect snippets、code layers。是設計意圖的結構，不是對設計的文字描述。

再加上 Code Layers — 在 Figma canvas 上直接跑的 code-backed prototype，而且可以反向「Extract designs」轉回可編輯的設計圖層 — 設計到 code 的完整迴圈終於在同一個工具裡關閉了。不是 handoff，是有兩種呈現形式的共同 artifact。

十年前，我們的工作是「把 handoff 做得更清楚」。今天，handoff 變成了 spec，spec 就在設計檔案裡面。

你的 Specs 品質現在是你跟任何 coding agent 合作的品質天花板。這讓寫 spec 變成一個 DesignOps 紀律，不再是事後補充。未來幾個月想清楚這件事的團隊，在 AI 輔助開發上會有結構性優勢 — 不是因為他們用了更好的 AI，而是因為他們給了更好的輸入。
