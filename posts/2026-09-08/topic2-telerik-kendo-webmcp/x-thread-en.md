---

**Tweet 2**
Let me explain what WebMCP means.

Today: AI agents interact with UIs through screenshots — they guess what's clickable from a visual. Like a human using a laggy remote desktop.

WebMCP: agents interact via a structured API that exposes what the UI is and what it does. Not a screenshot. A semantic description.

Same shift as div soup → semantic HTML.
Same API as screen readers.

---

**Tweet 3**
The Agentic UI Generator is the second notable update.

When AI generates a UI component, it now includes component-level accessibility by default:
→ ARIA roles baked in at generation
→ Keyboard navigation patterns included
→ Compliance guidance surfaced at step 1, not in a post-launch audit

A11y is in the generation step.
Not the review step.

**Tweet 5**
The connection between accessibility and agent-legibility is not metaphorical.

WebMCP uses the same accessibility tree that screen readers use.

When Telerik bakes a11y into AI-generated components, they're solving both problems at once.

Good design practice and agent-legible design are the same requirement.

**Tweet 7**
Every major component library is now racing to answer:

"Can an AI agent understand and operate this UI component reliably?"

That question has always been the accessibility question:
"Can a person with a disability understand and operate it?"

They've always been the same question.
Enterprise component vendors just made it explicit.
