# 主題一：Figma Agent 進入 FigJam 和 Slides
# 平台：小紅書
# 語言：繁體中文
# 日期：2026 年 11 月 24 日

---

## 標題
Figma agent 剛封閉了最後兩個 pipeline 缺口——完整的設計流程 AI 覆蓋長什麼樣

---

## 正文

Figma 在 11 月 23 日把 agent 功能帶進了 FigJam 和 Slides。加上 Dev Mode agent（11 月 19 日），設計流程 pipeline 現在全面覆蓋了。

完整的樣貌是這樣：

**→ FigJam（研究合成）** — 附加設計檔案、逐字稿、研究筆記 → agent 把它們整理成 board、找出連結、把想法推得更遠。真正被解決的瓶頸：你在合成開始之前光是組裝 context 就花掉的那一小時。

**→ Design canvas** — Agent 在這裡已經有一段時間了。生成、精修、迭代。

**→ Dev Mode（工程交接）** — 一個 prompt 就能檢視設計、比較版本、取得程式碼片段、批量下載資產。

**→ Slides（stakeholder 溝通）** — 把材料變成 draft presentation，為不同受眾調整 deck，縮短整份 deck 的 copy，對故事線給意見。

**5 件值得知道的事：**

1. **現在在所有付費方案都可用** — FigJam agent 和 Slides agent 都是。不需要新的訂閱方案。

2. **輸入品質 = 輸出品質** — Agent 從你附加的東西工作。有結構的研究筆記 → 有用的 board。分散、沒有標記的逐字稿 → 整理過的分散。這不是合成的捷徑。Brief 就是你的 artifact 品質。

3. **Slides 在做真正的 audience modeling** — 「為不同受眾調整」不是搜尋替換。Agent 在重新結構什麼被強調。在你信任它用在高風險簡報之前，先觀察它怎麼做這些決策。

4. **FigJam 和 Slides 支援特定 connector** — 設計檔案、逐字稿、研究筆記被明確列出。不是「附加任何東西」。有意為之的範圍設定。那個範圍是品質決策，不是限制。

5. **錯誤模式和 Dev Mode 不一樣** — Dev Mode 是確定性的（設計規格 → 程式碼）。FigJam/Slides 是詮釋性的（分散的 artifact → 建構的意義）。詮釋性 AI 的失敗模式很隱微：一切看起來有條理，但被建構出了錯誤的意義。建立一個 review 步驟。

**誠實的框架：**

如果你的研究 artifact 在這之前已經有良好結構，Figma agent 能為你省下可觀的時間。

如果你的研究流程是分散的，agent 給你的是你現有混亂狀態的更快版本。

瓶頸從 context 組裝移到了輸入品質。那是你在 agent 能幫你之前需要先修的東西。
