## THREADS POST — Long-form

I've been noting which pipeline gaps Figma has closed each week. Dev Mode agent (Nov 19) was the downstream end: engineering-side inspection, version comparison, code snippet generation, bulk asset downloads. That's the design-to-code handoff layer.

This week they closed the other two ends.

FigJam agent: attach design files, transcripts, research notes directly to a board and ask the agent to organize them, draw connections, or push an idea further. If you've ever spent an hour just getting your research artifacts into FigJam before you could start the actual synthesis work, this is the gap being addressed.

Slides agent: turn the same material into a draft presentation. Adapt a deck for a different audience. Shorten copy across the whole thing. Ask for feedback on the story arc.

The pipeline is now: FigJam (synthesis) → Design (canvas) → Dev Mode (handoff) → Slides (communication). Same agent, different surface, different trust calibration at each stage.

The FigJam use case is primarily about context assembly — the administrative overhead before the real thinking starts. The Slides use case is more interesting because "adapt a deck for a different audience" is not execution. It's audience modeling, which is a design judgment call.

The honest caveat is the same one that applies to every AI-assisted workflow: the quality of what goes in determines the quality of what comes out. If your research artifacts are scattered across Notion, Miro, three different Loom recordings, and an email thread, the FigJam board won't fix that scatter — it'll organize it. That's not nothing, but it's not synthesis either.

The input is now the brief. Structured research artifacts → useful FigJam board. Coherent slide structure before you ask the agent to adapt it → useful adaptation. The bottleneck moved from assembly to intake quality.
