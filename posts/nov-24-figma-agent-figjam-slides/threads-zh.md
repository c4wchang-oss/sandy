## THREADS 貼文 — 長篇個人反思

我一直在追蹤 Figma 每週封閉了哪些 pipeline 缺口。Dev Mode agent（11 月 19 日）是下游端點：工程側的設計檢視、版本比較、程式碼片段生成、批量資產下載。那是設計到交接層。

這週他們封閉了另外兩端。

FigJam agent：直接把設計檔案、逐字稿、研究筆記附加到 board，請 agent 整理它們、找出連結，或把想法推得更遠。如果你曾經花一小時只是把研究 artifact 整理進 FigJam 才能開始真正的合成工作，這就是被處理的缺口。

Slides agent：把同樣的材料變成 draft presentation。為不同受眾調整 deck。縮短整份簡報的 copy。請 agent 對故事線給意見。

Pipeline 現在是：FigJam（合成）→ Design（canvas）→ Dev Mode（交接）→ Slides（溝通）。同一個 agent，不同的介面，每個階段不同的信任校準。

FigJam 的使用場景主要是 context 組裝——真正思考開始之前的行政開銷。Slides 的場景更有趣，因為「為不同受眾調整 deck」不是執行。那是 audience modeling，是一個設計判斷決策。

誠實的前提和適用於每個 AI 輔助工作流的前提是一樣的：輸入的品質決定輸出的品質。如果你的研究 artifact 分散在 Notion、Miro、三個不同的 Loom 錄影和一個 email 討論串裡，FigJam board 不會修復那種分散——它會整理它。這不是沒有價值，但也不是合成。

輸入現在就是 brief。有結構的研究 artifact → 有用的 FigJam board。在你要求 agent 調整之前有條理的投影片結構 → 有用的調整結果。瓶頸從組裝移到了輸入品質。

現在在所有付費方案上都可用。

FigJam + Slides：研究合成 + stakeholder 溝通 = 兩個上游端點封閉。

Pipeline 完整了。研究 artifact 進 → 整理好的 FigJam board。材料 → 為你的特定受眾調整的 draft presentation。
