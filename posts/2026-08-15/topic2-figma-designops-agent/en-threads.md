# Threads Post — Figma AI Agent as Design System Maintainer (EN)
# Topic: Real-world testing of Figma AI agent confirms audit/maintenance strength, creation gaps
# Platform: Threads
# Format: Long-form personal reflection

---

Everyone testing the Figma AI agent keeps landing on the same finding: brilliant at maintenance, inconsistent at creation.

Give it structured, repeatable analytical work — audit naming conventions, flag detached components, document at scale, run gap analysis — and it's genuinely useful. Reliable in a way that manual audits aren't, because it doesn't get tired and doesn't skip the boring parts.

Give it a blank frame and ask it to invent a component that fits your system? That's where it drifts.

This isn't a model failure. It's a context problem. "Faithful to your design system" isn't a rule set the agent can learn from structure alone. It requires accumulated judgment — knowing how patterns evolved, why certain decisions were made, what the exceptions mean and why they're tolerated.

The job shift is real but it's not dramatic:

You stop being the person who does the maintenance audit.
You become the person who builds a system legible enough for AI to maintain.

That means:
→ Variable names that carry semantic meaning, not just hex codes
→ Component descriptions that explain when to use, not just what it looks like  
→ Auto layout everywhere — it's how the agent reads spatial intent
→ Component properties that define every state explicitly

These were always best practices. Now they're also your AI quality ceiling.

One concrete reframe: your design system documentation and your AI agent context parameters are now the same document. If you haven't written it for a human to understand in 30 seconds, the agent won't understand it either.

The janitor analogy only works if the space is clean enough to clean.
