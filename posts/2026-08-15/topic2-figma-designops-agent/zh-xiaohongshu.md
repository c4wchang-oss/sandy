**Title:**
我測了幾個月的 Figma AI agent，得出一個你可能不想聽的結論

---

**Body:**

最近一直有人問我 Figma AI agent 到底好不好用。

測了幾個月之後，我的結論是：它不是你期待的 design system 建造者，它是一個很好的 design system 清潔員。

**AI agent 做得好的事：**

✅ 稽核不符合命名規則的 variable
✅ 標記 detached component 和 hardcoded 數值
✅ 大規模幫 component 補文件
✅ 做 gap analysis，找出系統的空缺
✅ 發布前的一致性檢查

**AI agent 做不好的事：**

❌ 創造忠實於你既有系統 pattern 的新 component

不是模型問題，是 context 問題。你系統裡的隱性判斷，AI 暫時還學不走。

**這對我們的角色意味著什麼**

你不再是每季做一次 component 稽核的人。

你變成了「建立一個足夠讓 AI 維護的系統」的人。

這需要：

1️⃣ **語意化的 variable 名稱**
「Primary-Action-Blue」比「Blue-500」有用得多——AI 能讀懂意圖

2️⃣ **Component 描述寫「什麼時候用」**
不只是「長什麼樣」——解釋使用情境，agent 才能選對 component

3️⃣ **所有東西都加 auto layout**
這是 agent 理解你空間意圖的語言

4️⃣ **Component properties 定義每個狀態**
讓 AI 知道這個 component 的完整能力範圍

**最後一個重新框架**

你的 design system 文件，現在也是你的 AI agent 的 context 參數。

如果你沒有寫成讓人 30 秒看懂的樣子，agent 也看不懂。

清潔員的比喻只有在空間夠乾淨的前提下才成立。
