# X Thread — Figma Variable 自動綁定（繁體中文）
**主題：** Figma 7月16日更新：程式碼畫面匯入 canvas 時，現在自動綁定現有 variable
**角度：** 設計與程式碼的雙向循環不再是單向壞掉的。你的 constraint 架構現在對 AI 生成的輸出具有韌性。
**格式：** 8 則推文串

---

**Tweet 1（Hook）**
這週最無聊的 Figma release note，可能是設計系統團隊最重要的一則。

「程式碼畫面帶入 canvas 時，現在自動綁定你現有的 variable。」

一行字。讓我解釋它為什麼改變了一切。 🧵

---

**Tweet 2**
多年來，把程式碼畫面帶進 Figma 是這樣：

顏色 → 硬編碼的 hex 值。
字型大小 → 固定像素。
間距 → 死數字。

你整個 token 架構？消失了。每次匯入都要從零開始。

---

**Tweet 3**
這造成了設計系統工作裡最昂貴、最隱形的問題：

你定義 token → 工程師用它們開發 → 有人嘗試把畫面帶回 Figma → 它回來的時候是一堆硬編碼的值。

雙向循環的完整性預設是壞掉的。設計和程式碼之間的落差不斷擴大。

---

**Tweet 4**
Figma 剛推出的：當程式碼畫面進入 canvas 時，它會自動辨識並綁定到*你檔案裡已有的* variable。

顏色 token 重新連上。間距值重新連接。大多數 frame 的 auto-layout 也回來了。

雙向循環不再是壞掉的了。

---

**Tweet 5**
為什麼這對 AI 生成的 UI 特別重要：

當 AI 建構畫面 — Figma Make、Cursor、外部工具 — 輸出幾乎總是會破壞你的 token 結構。每個生成的 frame 都帶著硬編碼的值進來。

現在你可以匯入，設計系統的 token 層能撐過去。AI 可以生成。你的系統保持完整。

---

**Tweet 6**
最讓我興奮的使用場景：舊畫面的還原。

每個產品都有只存在於 dev 端的畫面 — 建構得很正確，但因為清理成本太高，從來沒有被帶進 Figma。

那個清理成本剛大幅降低了。把它們帶回來。重新綁定。精細化。

---

**Tweet 7**
對設計系統負責人來說，這是工作流程方向的轉變：

以前：「不要把程式碼畫面匯入 Figma，會毀掉你的 token 層。」
現在：「匯入吧。它們會自動綁定。然後再細修。」

交付剛剛變成真正雙向的了。

---

**Tweet 8**
真正的標題不是「Figma 為程式碼匯入加入了 variable 綁定」。

而是：Figma 讓你的設計系統對 AI 生成的輸出具有韌性。

你建構的 constraint 架構？AI 在匯入時再也無法破壞它了。

這是系統設計的勝利，不只是一個功能。
