**Title:** Framer Agents can now do accessibility checks — while you're still building

**Body:**

Framer's July 2026 Agent update quietly solved one of UX's oldest process problems.

**What's new:**
① A11Y layer attributes in Agent scope
② Page Effects (scroll animations, entrance transitions) now promptable
③ CMS Rich Text Video in Agent
④ Text Shadows and draggable interactions — AI-editable
⑤ GPT 5.6 Terra + Luna at 50% off until Aug 14

**The accessibility piece is the one I want to talk about:**

Before: Accessibility audit = a separate phase, a separate tool, a separate conversation. Usually at the end of the project. Usually after the "we're almost shipping" panic had already started.

Now: You're in the same Framer Agents chat building your homepage. You type: "run an accessibility check on this page — check form labels, image alt text, button accessibility." The agent scans everything and applies fixes.

Same session. Same tool. No export. No plugin switch.

**Why this changes the calculus:**

The reason accessibility got skipped wasn't that designers didn't care. It was that the tool lived at the end of the process. When the audit is in the workflow, "we didn't have time" becomes "we didn't ask."

That's a different kind of accountability.

**The 3 prompts I'd try first:**
1. "Check all images on this page for missing alt text and add it based on context"
2. "Run an accessibility audit on my navigation — ensure all interactive elements have descriptive labels"
3. "Apply proper A11Y attributes to all form fields and error states"

**For teams using Framer Agents:**
Page Effects are also in scope now — which means you can say "add a 300ms fade-in on scroll for this section" and it builds it.

The two things most likely to be deferred in any production push (motion and accessibility) are now both defaulting into the agent conversation.

There's no process argument left for leaving them out.
