## 主題：Framer Agents 七月 2026 更新 — 無障礙設計進入工作流程
## 日期：2026 年 8 月 4 日
## 建議封面圖比例：3:4

**標題：** Framer Agents 可以跑 accessibility check 了——而且是你做設計的當下

**內文：**

Framer 七月 2026 Agents 更新悄悄解決了 UX 領域一個老問題。

**這次更新了什麼：**
① A11Y 圖層屬性進入 Agent 操作範圍
② Page Effects（捲動動畫、進場 transition）現在可以用 prompt 控制
③ CMS Rich Text Video 進入 Agent
④ Text Shadow 和 draggable interaction——現在也能 AI 處理
⑤ GPT 5.6 Terra + Luna 打五折到八月十四號

**我最想講的是 accessibility 這一塊：**

以前的流程：Accessibility 稽核 = 獨立的階段、獨立的工具、獨立的對話。通常在專案快結束的時候，通常在大家已經陷入「快要上線了」的焦慮之後。

現在：你在 Framer Agents chat 裡做首頁。你輸入：「幫這個頁面跑一次 accessibility check——確認 form label、圖片 alt text、button 的 accessible name。」Agent 掃描全部然後幫你補上。

同一個 session，同一個工具，不用 export，不用切換 plugin。

**為什麼這件事改變了計算方式：**

以前 accessibility 被略過，不是設計師不在乎，而是工具住在流程的最末端。當稽核在工作流程裡，「沒時間」就變成了「沒開口問」。那是不同層次的問責。

**我會先試的三個 prompt：**
1. 「幫這個頁面所有圖片補上根據前後文的 alt text」
2. 「對我的 navigation 跑 accessibility 稽核，確保所有互動元素都有描述性的 label」
3. 「幫所有 form 欄位和 error state 加上正確的 A11Y 屬性」

**給正在用 Framer Agents 的團隊：**
Page Effects 也進入 Agent 範圍了——你可以說「這個 section 加一個三百毫秒的捲動 fade-in」然後它幫你做。

做任何產品 push 最容易被延後的兩件事——動態效果和無障礙——現在都預設在 agent 的對話流程裡了。

繼續省略這兩件事，已經沒有流程上的理由可以說了。
