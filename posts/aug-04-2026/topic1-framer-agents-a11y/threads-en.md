# Threads Post — EN
## Topic: Framer Agents July 2026 Update — Accessibility as Workflow
## Date: Aug 4, 2026

---

Framer Agents can now run accessibility passes.

Not as a separate tool. Not as an exported report. In the same conversation where you're building the page.

The July 2026 update added A11Y layer attribute support — which means you can prompt the agent to check your navigation for missing labels, add alt text to every image based on surrounding context, and apply ARIA metadata across interactive components. Then it does it. All of it. While you're still in the chat.

This landed alongside Page Effects support — scroll animations, entrance transitions, full-page motion — which means the two categories of work designers have historically deferred most (motion and accessibility) are now default agent capabilities, not afterthoughts.

I've been thinking about why this matters more than the feature list suggests.

The industry has said "build accessibility in, don't bolt it on" for twenty years. That advice was correct and mostly ignored, because the workflow didn't support it. Accessibility audits happened at the end because the tools lived at the end — separate plugins, separate checklists, separate conversations from the design process.

When the audit tool is the same tool building the thing, the excuse changes. It's no longer "we don't have time." It becomes "we didn't ask." That's a different kind of accountability.

The test I'd give every team after this update: at the end of your next Framer Agents session, make one more prompt. "Run an accessibility check on this page." See what it finds. See how long it takes.

If the answer is under five minutes, you have no remaining process excuse for skipping it.
