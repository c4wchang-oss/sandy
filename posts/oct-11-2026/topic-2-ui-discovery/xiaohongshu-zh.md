# Xiaohongshu Post — 繁體中文
## 主題：UI Discovery — 111k 個 UI 段落，預先打包成 AI Prompt
## 日期：2026 年 10 月 11 日
## 格式：評測 / 實用觀點

---

**標題：Senior UX 觀點 | 「讓它看起來像 Linear」現在是可以直接執行的 brief**

---

UI Discovery（AppMole）於 10 月 10 日推出。

2,600+ 個真實網站，3,800 個 iOS app，111,000+ 個 UI 段落。
每個：萃取出色板 + 字型 + 佈局模式。
每個：附帶給 Cursor / Claude Code 的 AI-ready build prompt。
MCP：你的 agent 直接瀏覽這個 library。

瀏覽免費，Pro 方案解鎖完整 library + AI 功能。

---

**為什麼這跟截圖圖庫不一樣：**

舊工作流程：
① 找到靈感截圖
② 用文字描述它（大概描述得很差）
③ 希望 agent 正確解讀

新工作流程：
① Agent 透過 MCP 瀏覽 111k 個結構化段落
② 選擇附有預萃取設計 token + 結構化 prompt 的段落
③ 用真實參考執行，不是語言近似

Library 已經做了 prompt engineering 的工作。這才是產品本身。

---

**我今年一直在追蹤的模式：**

BRDNA → 品牌 DNA 作為 agent 上下文（不是抽象描述）
Stitch → 直接拖入品牌 PDF，不是描述它
Open Inspector → 把競品 design system 導出為 Markdown
UI Discovery → 111k 個段落預先轉譯為 AI-ready 格式

一個持續的洞見：具體參考 → 比抽象描述更好的 AI 輸出。

---

**你仍然要負責的品質上限：**

參考消除了模糊性，但不增加判斷力。

① 正確參考 + 正確 IA = 
② 正確參考 + 錯誤 IA = 精緻但錯誤

UI Discovery 處理執行品質。
IA 決策——這是否是你的用戶實際任務的正確結構？——仍然是你的責任。

---

**誠實的說明：**

→「受啟發 = 一模一樣」在擁擠的市場（他們自己說的）
→ 優化執行品質，不是差異化
→ 完整 library 需要 Pro 方案

---

**最佳搭配 Impeccable 使用：**
參考（UI Discovery）→ 執行（agent）→ Audit（Impeccable 的 61 條規則）

這是現在完整的迴圈。
