**Tweet 2：**

每個都拆解成色板、字型和佈局模式，每個都附帶給 Cursor 和 Claude Code 的 AI-ready build prompt。還有 MCP 連接，讓你的 agent 直接瀏覽這個 library。

---

**Tweet 3：**
MCP 連接是真正的產品轉變。

以前：你找到一個參考，用文字描述它，希望 agent 理解。
現在：agent 瀏覽一個有 111,000 個段落的結構化 library——每個都有預先設計好的 prompt——agent 自己選擇參考。

Reference-over-description 在工具基礎架構層面的實現。

---

**Tweet 4：**
我今年一直在追蹤 reference-over-description 這個模式：

BRDNA Sequencer → 品牌 DNA 作為 agent 上下文
Stitch brand kit → 直接拖入視覺參考，跳過文字轉譯
Open Inspector → 懸停任何生產網站 → 將 design system 導出為 Markdown
Once UI 2.0 → design system 附帶自己的 agent harness

UI Discovery 是同一個模式在 library 規模的實現。111k 個段落已預先轉譯為 AI 能讀的格式。

---

**Tweet 5：**
真正的價值：「library 已經做了那個轉譯工作。」

這才是新的東西。不是圖庫——那本來就有。而是 111,000 個畫面被分析、拆解、打包成結構化的 AI prompt。

省去每次開發者說「讓它看起來像 Notion 的側邊欄」時要花的 prompt engineering 時間。

---

**Tweet 6：**
我一直在問的品質上限問題：

參考消除了模糊性，但不增加判斷力。

對錯誤 IA 的完美執行仍然是錯誤的 IA。「像 Linear 的設定頁，但用於醫療 app」可能參考了出色的視覺執行，但對實際使用情境有糟糕的資訊架構。

UI Discovery 給你執行品質。評估參考是否適合，仍然是你的工作。

---

**Tweet 7：**
來自產品本身的誠實告誡：

「在你的市場中，『受到啟發』可能讀起來像『完全一樣』。」

在擁擠的產品類別中，參考優化的是執行，而非差異化。Reference library 讓你容易 ship 出一個看起來像你的類別龍頭的東西——而那也是你的用戶已經看過的東西。

搭配對你的產品哪裡需要獨特的真實判斷。
