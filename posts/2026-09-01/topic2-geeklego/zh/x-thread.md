# X 推文串 — GeekLego：AI-Native 開源設計系統
# 平台：X (Twitter) | 語言：繁體中文 | 日期：2026-09-01
# 來源：https://geekyants.com/blog/geekyants-launches-geeklego-an-ai-native-open-source-design-system

---

**第 1 則（開場鉤）：**
我們為設計系統寫了 20 年文件。

為人類寫的。

GeekLego 同時也為 AI coding 工具寫了。

同一套系統，不同的受眾。

[1/8]

---

**第 2 則：**
GeekyAnts 剛剛開源了 GeekLego：一個建立在 Tailwind CSS v4 上的 AI-native 設計系統。

它結合了：
→ 可複用的 UI component
→ Design token
→ 文件
→ 機器可讀的 governance 規則

MIT 授權。地板剛剛抬高了。

[2/8]

---

**第 3 則：**
機器可讀的部分才是真正的信號。

GeekLego 可以告訴 Claude Code、Codex、Gemini CLI——以及任何支援 agent 的工具——確切的：
→ 如何使用每個 component
→ 如何套用 token
→ 適用哪些 accessibility 要求
→ 如何與 Figma 工作流程保持同步

[3/8]

---

**第 4 則：**
有 GeekLego 之前：AI 生成程式碼後才執行標準（審查、linting、手動修正）。

有 GeekLego 之後：標準在生成時就介入。

這是 governance 模型的轉變。不是執行，是預防。

[4/8]

---

**第 5 則：**
這其實是我們多年來一直在說的設計系統文件論述——只是延伸到了上一層。

一個命名清晰的 token 不只對開發者清晰。
它對 agent 也是清晰的。

你只是還不知道 agent 也是你的受眾。

[5/8]

---

**第 6 則：**
GeekLego 實際上是什麼：
一份為你整個前端寫的 AGENTS.md——直接內建在 component library 裡。

不是單獨加在上面的 governance 層。
Governance 就是系統本身。

[6/8]

---

**第 7 則：**
它提出的誠實問題：

機器可讀規則由誰來撰寫？

不是開發者，不是 AI。

是理解每個 constraint 為什麼存在的人。

這就是未來 5 年的 DesignOps 角色。

[7/8]

---

**第 8 則（行動呼籲）：**
設計系統的 ROI 論述剛剛擴大了：

不只是「更快的交付」和「一致的 UI」。

還有：「AI coding 工具繼承你的 constraint，而不是自己發明。」

這是 governance。這是基礎設施。這是資深設計師的論據。

[8/8]
