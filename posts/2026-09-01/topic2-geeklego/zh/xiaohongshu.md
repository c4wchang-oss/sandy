**標題：**
開源 AI 設計系統剛剛改變了你的 agent 寫程式的方式

---

**內文：**

GeekyAnts 推出了 GeekLego（8 月 28 日）——目前為止為 AI 生成時代設計的最清晰設計系統範例。

這是什麼改變，以及資深 UX 設計師為何應該關注 👇

**1/ 它是什麼**
GeekLego = 開源 AI-native 設計系統
→ MIT 授權，Tailwind CSS v4
→ 整合：component + design token + 文件 + 機器可讀 governance 規則

**2/ Governance 層**
它告訴 AI coding 工具確切的：
→ Claude Code：如何使用每個 component
→ Codex：如何套用 design token
→ Gemini CLI：要遵循哪些 a11y 要求
→ 所有 agent：如何與 Figma 工作流程同步

**3/ 關鍵的時機轉變**
以前：程式碼生成後才執行標準
現在：在生成時就介入標準

這是預防，不是修正。這才是真正的 governance 模型改變。

**4/ 對設計師的意義**
你的設計系統現在同時有 2 個受眾：
→ 人類（開發者、PM）
→ Agent（AI coding 工具）

對 agent 重要的規則？就是 DesignOps 一直以來在乎的：component 意圖、token 語意、constraint 原因。

**5/ 開源的影響**
MIT 授權 = 地板移動了。每個使用 GeekLego 的團隊都繼承了相同的 governance 基準線。你的優勢：意圖被記錄得夠清晰，讓 AI 能正確套用。

**6/ 真正的問題**
誰來寫機器可讀規則？
不是開發者，不是 AI。
→ 是理解每個 constraint 為什麼存在的人。
這是設計領導力的職位。

**7/ 誠實的注意事項**
GeekLego 是基礎層。你的設計系統品質上限仍然是：
→ 你的 token 命名品質
→ 你的 component 意圖文件
→ 你的 constraint 原因

工具只在你投入的品質範圍內有效。
