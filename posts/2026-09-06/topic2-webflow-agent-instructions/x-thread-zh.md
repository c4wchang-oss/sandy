**Tweet 1（開場）**
Webflow 推出了「Agent Instructions Generation」。

給它你的 live 網站 → 它自動幫你寫品牌指南。

輸出的結果，會比你做過的任何設計審查都更誠實地揭露你的設計負債。

🧵

---

**Tweet 2**
它的運作方式：

AI 讀取你的 live 網站 — 品牌聲音、設計系統元件、圖片模式、CMS 結構 — 為每個類別自動生成一份草稿文件。

之後所有編輯你網站的 agent 都會把這些當作 context 參考。

---

**Tweet 3**
令人不舒服的部分在這裡：

它讀取的是網站上實際存在的東西。
不是你的設計意圖。
不是原始的品牌指南說了什麼。

所有的例外處理、一次性修改、遺留元件，全部都被納入。

---

**Tweet 4**
這份自動生成的「設計系統」是一面鏡子。

如果你的網站在 4 個元件裡有 7 種藍色變體，指南就會寫 7 種藍色變體。

agent 按照這些指南操作，就會忠實地複製你的設計不一致性。

---

**Tweet 5**
這其實意外成為我見過最有用的設計負債工具之一。

跑 Agent Instructions Generation 不是為了設好就放著不管。

跑它是為了看 AI 接觸你的網站時會看到什麼。

然後修掉你不想被編碼成「品牌標準」的部分。

---

**Tweet 6**
沒有人在問的治理問題：

誰在 agent 遵循這些指南之前先審查它們？

「這是從我的網站生成的」≠「這反映了我的設計意圖」。

設計師的新工作：instruction architecture 審查者。

---

**Tweet 7**
我實際上會怎麼做：

1. 生成指南
2. 像讀審查報告一樣讀它 — 哪裡不對？
3. 先修掉網站上最嚴重的不一致
4. 用真實意圖編輯這些指南
5. 然後讓 agent 照著做

順序很重要。生成 → 審查 → 修正 → 信任。

---

**Tweet 8（結尾）**
這個模式現在到處都是：
Webflow Agent Instructions、v0 API、CLAUDE.md、design.md。

每個平台都在要求設計師為 AI 記錄設計意圖。

最有優勢的設計師：那些把文件當作基礎設施，而不是行政工作的人。
