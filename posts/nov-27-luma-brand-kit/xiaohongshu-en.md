## XIAOHONGSHU POST

**Your brand character's face is now a reusable asset — Luma Brand Kit + Character Library**

Luma launched Brand Kit and Character Library on Nov 25. Here's the practical breakdown:

**The core problem they're solving:**
AI improvises. 100-asset campaign later, your logo shifted, your product color is off, and your brand mascot looks like a different character by scene three. This isn't a prompt problem — it's a constraint architecture problem.

**What Brand Kit does:**
- Upload logos, fonts, colors, products, references, brand rules once
- Or drop in your website URL → Luma drafts a brand kit for you to review
- Tie to a board with `#brandkit` → every generation reads it automatically
- No re-prompting, no drift correction session after each batch

**What Character Library does:**
- Store face, body, wardrobe, expressions, environments as a character resource
- Reference with `@character` in any board
- Character evolves? Update the library → all future generations use the updated version
- First platform to treat character face consistency as a formal brand asset type (same level as a logo)

**The workflow:**
1. Build your Brand Kit (upload guidelines doc or website URL)
2. Set up Character Library for each brand character
3. Open a board → `#brandkit` + `@character` → describe your brief
4. Agent generates consistent campaign assets reading both resources

**What "evaluates alignment" actually means:**
Luma says the system evaluates whether output aligns with your brand rules. This is monitoring, not enforcement. The agent flags drift — it doesn't architecturally prevent it. Know the difference before you run 100 assets unattended.

**Honest caveats:**
- Brand Kit is in research preview (beta)
- URL-based drafting reads your deployed site = current state, not documented intent; audit the draft before running
- Character consistency for brand characters ≠ realistic human likeness — verify for your specific use case
- No pricing details in the announcement

**The bigger pattern:**
Brand Kit follows Stitch, Higgsfield, Automo — same principle: brand constraints loaded once, applied automatically. Character Library is new: face = named constraint, not an image you re-describe each time. That distinction matters at production scale.
