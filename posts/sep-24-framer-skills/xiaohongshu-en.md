**Title (for cover card):**
Every AI design tool shipped "Skills" in the same week. Here's what senior designers need to know.

---

**Body:**

Framer launched Skills on Sep 22. Figma launched Custom Skills the same day. Notion launched Skills four days earlier. CapCut launched Skills in August.

They're all the same concept: reusable instructions that teach the AI how you work, specific to each tool. This is not a coincidence. It's infrastructure becoming standard.

Here are 5 things worth understanding before you start building skills everywhere:

**1. Skills are encoded judgment, not prompt shortcuts**
A Framer Skill can reference your actual @components, @styles, and @pages — the AI auto-invokes it when your task matches the description. This is not a macro. It's a standing brief for how your design system thinks.

**2. Template remix changed this week**
Skills travel with remixed Framer projects. Template authors now package their design direction alongside the components. If you sell templates, what you're actually selling is now the judgment behind the layout.

**3. `/skills` is the fastest way to start — and the riskiest**
Type `/skills` and the agent writes a skill from your last conversation. It captures what you did in that session. NOT why you did it. NOT the context that made that call right. Audit every auto-generated skill before publishing to your team.

**4. Auto-invoke reliability = description quality**
Framer's agent reads your skill's description to decide when to invoke it. Vague description = wrong invocations. This is the exact same problem as naming components in a design system. DesignOps. Still yours.

**5. The multi-tool conflict problem is real**
You now have Figma skills, Framer skills, Notion skills, Cursor instructions. Different formats, different sessions, different levels of accuracy. When a task crosses tools, the wrong one will run first. Nobody has solved skills governance yet.

The tools are ready to learn how you work.
The question is whether you've ever written down why.
