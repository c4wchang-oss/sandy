---

**標題：** Attest 讓你的研究庫變成複利資產 — 實際改變了什麼

---

🎯 **發生了什麼：**
Attest 秋季更新，2026 年 9 月 10 日發布。三個關鍵更新：
- **Results API**：每個完成的研究自動落地到你的資料倉儲或 BI 工具 — 不再需要匯出 CSV
- **MCP server**：從 Claude、ChatGPT 或任何 AI 工具查詢你的整個研究庫
- **推送說話 AI 訪談**：受訪者有真正的思考時間再錄製

---

📌 **Results API + MCP 組合為什麼是結構性的轉變：**

舊的研究工作流程：
1. 做研究 → 匯出 CSV → 寄給 data 工程師 → 等待上傳 → 另外分析

這次更新之後：
1. 做研究 → 自動落地到資料倉儲
2. 請 AI 工具跨你所有研究合成 — 同樣的問題在不同市場；這波次對比上一波次；12 個月來改變了什麼

研究從一系列一次性報告，變成複利的研究庫。每次新增研究，你所有已完成的研究都增值，因為 agent 現在可以回頭把它都包含進去。

---

📌 **MCP server 具體能做什麼：**

1. 「我們所有研究裡，關於 [主題] 我們知道什麼？」→ 一個合成的答案，不是五個分頁
2. 「對 [產品領域] 的看法在過去 4 個波次怎麼變化？」→ 趨勢合成，不用手動重讀
3. 「英國客戶對比德國客戶怎麼說 [功能]？」→ 跨市場比較，不用另起一個分析專案
4. 「做完了」的研究繼續在貢獻 — 每個新研究讓之前所有的研究增值

---

📌 **推送說話的訪談格式改變（為什麼對定性研究真實性重要）：**

AI 主持訪談一直有一個一致的批評：受訪者沒有思考時間。系統走得太快，回答感覺反射性而非深思熟慮。

舊格式：問題出現在螢幕上 → 受訪者立即打字
新格式：主持人朗讀問題 → 受訪者按下開始錄製 → 完成後再按一次

錄製前有思考時間 = 更經過考慮的回答。這是基本的定性訪談原則 — 你希望受訪者在回應之前已經處理過問題，而不只是對它有反應。這個格式在其他 AI 主持的平台上已經是標準，是朝向更好定性研究真實性的有意義的一步。

---

📌 **對資深 UX 研究員的意義：**

1. **瓶頸又移動了。** 不是「我們負擔得起做這個研究嗎？」（2020）→ 不是「我們能不能取出資料？」（2023）→ 現在：「我們的研究庫結構夠不夠一致讓 agent 從中合成？」

2. **研究設計變得更重要，不是更不重要。** 模糊的研究目標 = 當 agent 跨 20 個研究查詢時，合成也是模糊的。資料更多不等於答案更好，問題框架更好才等於答案更好。

3. **跨波次術語現在是基礎設施。** 不同研究用稍微不同的語言描述同一個概念，跨波次合成就崩潰。一致性是技術需求，不只是風格偏好。

4. **研究分類法是你的 agent context。** 你怎麼標記、打標籤、結構化研究，決定了 agent 能從你的 MCP server 取出什麼。研究庫的 IA = MCP 品質天花板。

---

✅ **怎麼讓你的研究庫準備好 MCP：**

1. **稽核跨波次術語一致性** — 相同的概念在你所有研究裡用了相同的語言嗎？
2. **審查研究目標的具體性** — 只看目標陳述，agent 能理解每個研究設計來回答什麼嗎？
3. **一致地標記你的研究庫** — 按主題、市場、產品領域、時間段
4. **找出有時效限制的研究** — 3 年以上的研究，如果你的產品或用戶有大幅變化，可能降低合成品質

---

⚠️ **誠實的 caveat：**
Results API 和 MCP server 在 early access（企業客戶優先，更廣泛推出沒有時間表）。AI 主持抓到模式和主題，不是訓練有素的主持員會注意到的猶豫、語氣和言下之意。研究庫只有在研究結構一致時才能複利 — 垃圾進，垃圾出，在更大規模下更快。Attest Explore（AI 主持定性研究）在高風險研究場景中不能取代有技巧的人類主持員。

---

💡 **重新框架：**
你不是在寫研究報告。
你是在建一個加入越多越有價值的研究庫。
研究是內容，結構是基礎設施。
資深研究員現在設計的是基礎設施。
