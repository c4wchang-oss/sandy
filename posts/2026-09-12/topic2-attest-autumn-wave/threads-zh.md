# Topic 2: Attest 秋季更新 — 研究基礎設施作為設計介面
# Platform: Threads | Language: Traditional Chinese
# Date: Sep 12, 2026 | Format: 長篇個人反思 + 短版要點
# Source: https://www.askattest.com/blog/attest-news/whats-new-in-the-attest-autumn-wave (Sep 10, 2026)

---

你的研究不是卡在研究做得不夠多。

它卡在輸出放在一個什麼都讀不到的資料夾裡。

Attest 在 9 月 10 日發布了秋季更新，最大的兩個新增是基礎設施，不是功能：Results API 和 MCP server。

Results API 讓每個完成的研究自動落地到你的資料倉儲或 BI 工具。不再需要匯出 CSV，不再需要寄給 data 工程師等手動上傳。研究完成，資料流出。

MCP server 是更重要的結構性轉變。你現在可以把任何 AI 工具 — Claude、ChatGPT、Cursor — 指向你所有的 Attest 研究歷史，跨一切查詢。跨波次合成。時間趨勢。跨市場比較。在一個答案裡，從一個問題開始。

這改變了研究庫的本質。在這之前，研究是一系列一次性的報告。研究完成，報告送出，就安靜下來了。有了 MCP，每次新增研究，你所有已完成的研究都增值。研究庫複利。

品質天花板還是你的研究問題。MCP 讓研究庫可以被查詢，它不改善裡面有什麼。模糊的研究目標流入模糊的合成。跨波次框架不一致 — 不同研究用稍微不同的語言描述同一個概念 — 讓跨波次比較崩潰。瓶頸從 2020 年的「我們負擔得起做這個研究嗎？」，到 2023 年的「我們能不能取出這些資料？」，到現在：「問題值不值得問，而且結構夠不夠一致讓 agent 能建立在它上面？」

推送說話的訪談格式是 AI 主持運作方式的真實改善。一個持續的批評是 AI 主持的訪談步調太快 — 受訪者沒有思考時間，回答感覺反射性。Attest 的新格式直接解決了這個問題：主持人朗讀問題，受訪者按下開始錄製，完成後再按一次。思考時間內建進去了。這個格式在其他 AI 主持的平台上已經是標準，更接近好的定性研究實踐應有的樣子。

資深研究員的工作現在更清晰了 — 而且它在個別研究的上游。研究架構設計。問題框架。招募標準。跨波次分類法。研究庫一致性。那些決策決定了你的 MCP server 回傳的是洞察還是噪音。交付物變便宜了，讓它有價值的判斷沒有。
