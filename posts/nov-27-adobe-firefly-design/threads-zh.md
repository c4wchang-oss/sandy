# 主題一：Adobe Firefly Design (beta) + Creative Agent 全面進駐 CC 工具
# 平台：Threads
# 語言：繁體中文
# 日期：2026 年 11 月 27 日

---

## THREADS 貼文 — 長篇個人反思

Adobe 在 11 月 25 日推出了 Firefly Design beta。這是一個單一 workspace，結合了點陣、向量、動態、3D 和印刷設計——以前這些工作分散在六個不同的 CC app。Creative Agent 正在以「AI Assistants」的形式推出到 Premiere、Illustrator、InDesign、After Effects 和 Frame.io。在 Photoshop 裡它是一個獨立的 beta app。

這個公告裡有兩件事我覺得值得停下來想。第一個是 plan mode。在 agent 執行之前，它先給你看它的計劃。你審查、編輯、批准，或切換到完全自主模式。這是我一直在談的兩階段架構——生成前約束定義，批准步驟時人在迴圈中。重要的不是功能本身；是它對 Adobe 認為信任問題在哪裡的暗示。他們決定問題是「在你說好之前就做事的 agent」，不是「在你說好之後做錯事的 agent」。這是正確的讀法。

第二個是 local MCP 整合。這在 private beta，目標是 2027 年初，所以現在還沒有。但意圖是：外部 agent（Claude、Cursor、任何 MCP 客戶端）直接連接到你自己機器上的 Photoshop、Illustrator、Premiere、After Effects。專案檔案留在你的電腦上。圖層、向量、序列保持可編輯。Agent 把生產來源當作它的上下文，不是截圖。

如果你一直在追蹤 web 平台 MCP 收斂——Webflow、Elementor、Framer，全部在 46 天內——這是同樣的弧線，現在延伸到桌面創意生產 app。那些 web 平台從公告到完成大約花了六週。我預期桌面會花更長時間，因為本地文件存取和多個宿主 app 的複雜性，但方向是清楚的。

誠實的前提：Firefly Design 在 beta，出貨時間不明。Creative Agent 在大多數 app 中是 beta，能力水準不均。品牌偏好設定儲存是對 agent 的參考輸入，不是結構性約束執行——agent 讀取你的指南文件，它不會在架構上防止指南違規。「AI Assistants」是 Firefly 的重新品牌；不是所有助手都還在使用 Creative Agent。

我在觀察的部分：Local MCP 是這件事對專業生產流程變得重要的時刻。當外部 coding agent 能夠打開一個 Illustrator 檔案、讀取實際的圖層結構、修改特定路徑、然後交還——那時桌面創意層的生產檔案缺口才算真正閉合。在那之前的一切仍然是「生成然後希望」的互動。

Plan mode 是正確的設計決策：agent 提案，你批准，然後執行。兩階段信任架構在平台層。

我真正在看的部分：Local MCP 整合（private beta，目標 2027 年初）。當外部 agent 能讀取和編輯實際的 Photoshop/Illustrator/Premiere 專案檔案，生產流程才算端到端 agent 可讀。那是值得追蹤的弧線。
