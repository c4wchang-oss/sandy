**Tweet 2：**
OpenDesign（Apache-2.0，local-first）本週推出了協作 workspace：一個可以和你現有 coding agent 一起工作的開源 vibe design 環境。

17 個 BYOK adapter，150+ 設計系統，DESIGN.md 可攜帶。

---

**Tweet 3：**
Adapter 列表很重要：
Claude Code、Codex、Cursor、Gemini CLI、Grok、DeepSeek、Kiro、Kilo、Qwen、OpenCode、Mistral、GitHub Copilot CLI，以及更多。

切換 agent 是改配置，不是重新設計。你的設計工作流程不綁定於單一 provider。

---

**Tweet 4：**
工作流程：
選設計系統 → 描述畫面 → agent 寫出可用的 HTML prototype → 即時預覽 → 分享給團隊 → 成員直接在設計上留言 → agent 依留言修改 → 匯出或交付

本週新功能：整個團隊共享的專案、設計系統和 skills。

---

**Tweet 5：**
設計系統：150+ 個開源選項，或從網站 URL、GitHub repo、Figma 檔案生成一個。

顏色、字型、間距、元件塑造 agent 製作的每個 prototype。Constraint document 就是 brief。

DESIGN.md 可攜帶，就是 Claude 原生讀取的、Vercel 使用的、Onefold 自動生成的同一個格式。

---

**Tweet 6：**
誠實比較——Claude Design vs. OpenDesign：

Claude Design：零設定摩擦，限 Anthropic，託管
OpenDesign：需先設定好 agent，任何 agent，local-first，Apache-2.0，你擁有所有檔案

對有現有 Cursor 或 Codex 投資的團隊來說，可攜帶性才是真正的論據。

---

**Tweet 7：**
需要了解的限制：
- 需要先設定好 coding agent（不像 Claude Design 內建於對話那麼無縫）
- 輸出品質上限 = 你的 agent 品質 × 你的 brief 品質
- 有託管雲端模式，適合不想本地設定的團隊
- 設計系統品質依然決定 AI 輸出品質的下限
