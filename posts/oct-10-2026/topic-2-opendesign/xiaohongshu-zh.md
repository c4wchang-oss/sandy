# Xiaohongshu Post — 繁體中文
## 主題：OpenDesign — 支援任何 coding agent 的開源 vibe design workspace
## 日期：2026 年 10 月 10 日
## 格式：評測 / 比較

---

**標題：Senior UX 觀點 | OpenDesign = 任何 agent 都可用的開源 Claude Design（17 個 adapter）**

---

Claude Design 上週變成 Claude 的原生功能了。但如果你的團隊用 Codex？或 Cursor？

OpenDesign 本週推出了協作 workspace。這是它的概況。

---

**支援的 agent（17 個 BYOK adapter）：**

- Claude Code、Codex、Cursor
- Gemini CLI、Grok、DeepSeek
- Kiro、Kilo、Qwen、OpenCode
- GitHub Copilot CLI、Mistral 以及更多

切換 = 改配置，不是換產品。

---

**工作流程：**

① 從 150+ 個開源設計系統中選擇
   （或從網站 / GitHub repo / Figma 生成）
② 描述你要建什麼
③ Agent 寫出可用的 HTML prototype
④ 即時預覽——需要的話直接編輯
⑤ 分享給團隊 → 成員在設計上留言
⑥ Agent 依留言修改
⑦ 匯出 HTML/PDF 或移交工程師

---

**本週新功能：團隊 workspace**

- 跨團隊共享專案
- 共享設計系統 + skills
- 在即時 prototype 預覽上留言
- Workspace 計費
- Apache-2.0，local-first，你自己擁有所有檔案

---

**誠實比較：**

| | Claude Design | OpenDesign |
|---|---|---|
| 設定 | 零摩擦 | 需先設定好 agent |
| Provider | 限 Anthropic | 任何 agent（17 個）|
| 檔案 | 託管 | 本地擁有 |
| 授權 | 專有 | Apache-2.0 |
| DESIGN.md | ✓ | ✓ |
| 團隊 WS | ✓ | ✓（新功能）|

---

**OpenDesign 真正的論據：**

如果你的團隊已經投資了 Cursor 或 Codex 工作流程，你可能不希望設計工作流程再被鎖定在第三個 provider。

BYOK 設計 = 可攜帶工作流程 = AI provider 改變時的未來靈活性。

無論如何，設計系統品質依然決定輸出品質的上限。
