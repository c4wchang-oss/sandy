## 正文

「agent 改了錯的 component」這個問題終於有了一個直接的解法。

Ilse 是一個工具列，疊在你跑起來的 React app 上面。點擊一個元素，描述要改什麼，你的 coding agent 收到的是精確的檔案路徑、行號和 design token——不是你的文字描述。

**實際怎麼用：**

1. **開啟 app** — 在專案資料夾跑 `npx ilse-design@latest`，自動偵測 Next.js、Vite、Remix、Astro。
2. **點擊並說明** — 點擊任何元素，寫下要改什麼。Agent 收到精確的 context，不是一段文字說明。
3. **Panel 調整** — 用你自己的 design token 調整間距、字型、顏色。簡單的修改直接生效，不花 AI，不花 token。
4. **Component library** — Ilse 自動從你的 component 和 token 生成 `DESIGN.md`。你的 agent 就不會再自己發明新按鈕了。

**Pro 版（預購，11 月出貨）：**
Test mode — 描述一個使用者流程（「買那盞燈」），Ilse 在你的真實 app 上自動走完，回報哪裡出問題。

**對 UX 設計師來說為什麼重要：**
「視覺指點作為 agent context」這個模式在 2026 年已經被確認三次了：MagicPath（canvas 元素）、Skisso（live CSS）、Ilse（dev app）。每次都比文字描述更精準。

**誠實的部分：**
- 只支援 React
- 需要自己有 coding agent 訂閱（Claude Code、Cursor、Codex、Gemini）
- Pro 在預購階段，test mode 11 月出貨
- 非常早期，solo founder，但問題陳述是今年最精確的之一

由一個花了 9 年做設計才轉向程式碼的設計師建造。那份挫折感是真實的，解法也是直接的。
