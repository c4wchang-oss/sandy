**標題：**
AI 可以直接幫你 build onboarding flow 了——但有個前提

---

**內文：**

Usertour 發布了有 67 個工具的 MCP server，讓 AI agent（Claude、Cursor）可以直接 build、publish、debug in-app onboarding flow。

作為 UX 設計師，這對你的工作流程實際上意味著什麼：

**改變了什麼**
✦ AI agent 現在可以端到端完整寫出 onboarding flow
✦ 驗證是內建的——結構有問題，ship 前就被抓出來
✦ 整合方式：Claude Code 或 Cursor + Usertour = 不用手動碰 UI 的 onboarding

**Usertour 在自己文件裡說的重點：**
「要求一個聚焦的、production-ready 的體驗，而不是所有按鈕的通用導覽。」

「所有按鈕的通用導覽」= AI 在沒有清楚 brief 時的預設值。速度快、結構乾淨，什麼都沒教。

**這對你角色的意義**

📌 第一步：定義新使用者在前 5 分鐘什麼叫「成功」
📌 第二步：找出他們需要完成哪 2–3 個動作才能到達那裡
📌 第三步：指定要顯示什麼、延後什麼、完全跳過什麼
📌 第四步：把這些給 AI——67 個工具負責 build

**資深設計師在這裡真正重要的技能：** 知道使用者實際上需要理解什麼，以及用什麼順序。AI 可以排版、格式化、ship。它沒辦法幫你做優先排序。

**實話說：** 這不會取代 UX thinking。它只是讓一個模糊的 brief 更快 ship 出去。如果你的 brief 一直是弱點，現在你知道了。
