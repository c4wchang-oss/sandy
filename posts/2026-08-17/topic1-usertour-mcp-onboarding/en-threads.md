# Topic: Usertour v0.9.1 ships MCP server with 67 tools for AI-built onboarding (Aug 15, 2026)
# Platform: Threads
# Format: Long-form personal reflection

---

The onboarding flow was always the most important document in a product launch. We just spent most of our time on the wireframes instead of the thinking behind them.

Usertour's new v0.9.1 changes something: it ships an MCP server with 67 tools so AI agents can build, publish, and debug in-app onboarding flows directly. Claude Code, Cursor — they can now write the flow, run it, catch broken steps, and ship it without a designer touching the UI manually.

The part of their docs that stuck with me: "Inspect the page and design system first; then ask for one focused, production-ready experience rather than a generic tour of every button."

"A tour of every button." That's the AI default without guidance. You've seen it — every feature highlighted in sequence, no sense of priority, no understanding of what a new user actually needs to understand first. It ships fast. It teaches nothing.

What that warning in the docs is actually telling you: the quality ceiling for AI-built onboarding is brief quality. Always was. Now there's less distance between a vague brief and a shipped product.

For me, this is clarifying rather than alarming. The parts of onboarding design I always found most valuable — figuring out what the user needs to learn and in what order, deciding what to hide vs. highlight at launch, defining what "success in 3 minutes" actually means — none of that is in the 67 tools. That's still a human call.

The shift is: that call is now the primary deliverable. Not the annotated wireframe. Not the Figma prototype. The specification, written clearly enough that an AI can build from it without guessing.

If you're a senior designer who's been frustrated that "the brief" was never treated as seriously as the execution — this is your moment. The brief just became the only interface.
