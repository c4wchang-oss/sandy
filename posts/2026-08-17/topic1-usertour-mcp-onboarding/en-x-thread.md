**Tweet 1 — Hook**
Usertour shipped an MCP server with 67 tools.

AI agents can now build, publish, and debug in-app onboarding flows directly.

The designers I know are skipping past the headline. They shouldn't. 🧵

---

**Tweet 2**
What actually shipped:
- A v2 REST API with full coverage of steps, conditions, triggers, themes
- An MCP server exposing 67 tools to Claude, Cursor, and any compatible agent
- Validation at write time: bad structure gets rejected before it ships

---

**Tweet 3**
Usertour's own advice for prompting AI to build onboarding:

"Inspect the page and design system first. Ask for one focused, production-ready experience rather than a generic tour of every button."

That sentence is a design brief compressed into a warning.

---

**Tweet 4**
"A tour of every button" is what AI defaults to without guidance.

You've seen these in the wild. Every feature highlighted. No prioritization. No sense of what the user actually needs to learn first.

That's not a model problem. It's a brief problem.

---

**Tweet 5**
The onboarding flow was always a brief in disguise.

"Walk new users through the core workflow" is not a brief.

"Help a first-time user complete their first X within 3 minutes, using only the features they'll use daily" is closer.

---

**Tweet 6**
The senior designer's job didn't change — it just became more visible.

Before: translate brief → wireframes → review → handoff.

Now: brief → AI builds → validate → ship.

The brief is now the primary deliverable. It was always the most important part. Now it's the only interface.

---

**Tweet 7**
What AI still can't do: know what the user needs to understand.

It can structure. It can format. It can run the 67 tools.

It cannot tell you which 3 things matter most in your onboarding. That's your job. Still.

---

**Tweet 8**
The toolbox has 67 tools.

The question isn't which tool to use. It's what you're trying to teach and why it matters in that order.

Write the brief like that. The rest follows.
