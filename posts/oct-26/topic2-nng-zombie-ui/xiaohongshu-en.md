**Title:**
NNG: AI saves UX time. But most designers feel "lukewarm." Here's the real issue.

---

**Body:**

The NNG survey is out. AI consistently saves time on UX work. And most practitioners feel... neutral. Not excited. Not frustrated. Just meh.

As a senior UX designer who's been tracking this closely, here's what I think is actually going on:

---

**The Gap Nobody Talks About:**

"AI saves time" = true at the generation step
"AI saves time end-to-end" = unclear

One team's 2-day hackathon with Claude + ChatGPT + Copilot:
→ Products looked nearly finished by hour 6
→ Full days of verification before anything actually worked

Generation time ≠ total project time. Most estimates still confuse these two numbers.

---

**The Zombie UI Problem (Stripe named it this week):**

"Zombie UI" = prematurely polished, generic AI-generated interfaces that look complete but have zero brand soul.

They're functional. Visually finished. Completely defensible in a review. And completely not yours.

The dangerous part? Zombie UI doesn't look broken. It looks fine. That's exactly why it ships.

---

**What Actually Fixes It:**

① Stripe's approach: Command-line brand constraints baked INTO generated code before human review — structural constraints that run AT generation time, not after

② Miro's approach: A skill that front-loads design system components + usage rules + examples into agent context BEFORE the agent starts building

③ The principle: Pre-generation constraint beats post-generation correction. Every time.

---

**The Diagnostic Question Your Team Should Ask:**

Don't ask: "does AI save time?"
Ask: "does AI save time end-to-end?" (generation + verification + correction)

Document this per task type. That number changes leadership conversations.

---

**Senior UX Takeaway:**

Lukewarm ≠ tools are bad.
Lukewarm = calibration gap between how fast generation is and how slow trust is to build.

Front-load constraints. Measure end-to-end. Document everything.
