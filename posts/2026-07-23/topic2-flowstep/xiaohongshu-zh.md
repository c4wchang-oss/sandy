🤯【大多數 AI 設計工具是螢幕工廠】

我這週在測試 Flowstep。

我的結論：這是目前唯一一個工具邏輯和 UX 邏輯真正對齊的 AI 設計工具。

讓我解釋。

---

📱【Flowstep 是什麼？】

Flowstep 是一個 AI 設計工具，從文字 prompt 生成完整的多螢幕 user flow，而不是單一畫面。

核心功能：
✅ 一個 prompt → 完整 6-8 個畫面的 user journey
✅ 選擇任何畫面 → 說「生成下一步」→ AI 自動推斷
✅ Canvas 從一開始就是 code（React + TypeScript + Tailwind）
✅ 接受 DESIGN.md 作為設計規範輸入
✅ MCP 整合 Cursor / Claude Code / Windsurf
✅ ⌘C/⌘V 直接 paste 進 Figma，不需要 plugin

---

🔑【最重要的設計決策：UI is code from the start】

在 Flowstep 裡，沒有「把設計稿轉成 code」這個步驟。
每個在 canvas 上的元素，同時就是 React 輸出。

handoff 不是一個動作，它從一開始就是同一件事。

這個概念轉變值得停下來想一下。

---

🧠【為什麼「flow 思考」很重要？】

我們用了這麼多年的設計工具，都在訓練我們用「screen」思考：
→ 做首頁、做登入頁、做 dashboard...

但 UX 的本質是設計 journey：
→ 用戶從哪裡來、遇到什麼、下一步是什麼、如果出錯了呢？

Flowstep 是第一個把工具邏輯和 UX 邏輯對齊的工具。

---

💡【DESIGN.md 作為 context 輸入】

這是我最喜歡的功能之一。

你可以把 DESIGN.md（設計系統規範）丟進去作為 context。
AI 在你的 constraint architecture 裡生成，不是對著它生成。

你的設計系統成為 AI 的邊界，不是它的障礙。

---

🎯【什麼時候用 Flowstep 最有效？】

✅ product direction 已經清楚
✅ 需要快速生成完整 user journey
✅ 需要同時輸出設計稿 + 開發用 code
✅ 有 DESIGN.md 或 design system 規範
✅ 需要驗證 flow 邏輯（missing states / dead ends）

❌ 不適合：early research、conceptual exploration

---

📝【資深設計師的老實話】

Flowstep 最大的價值不是「快」。

是強迫你在生成的時候，把整個 flow 的 UX 邏輯驗證一遍。
AI 會把你跳過的 missing state、dead end 浮現出來。

這不只是生成工具，這是一個讓你想清楚的機制。
