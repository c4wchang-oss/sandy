Cursor 這週推出了 Auto-review，他們用來描述這個功能的框架，是我今年讀到關於 agentic UX 設計最清楚的一句話：「自主性是刻度盤，不是開關。」

運作方式：一個 classifier agent 在上層 agent 執行動作之前先審查它，評估基準不是抽象的風險分數，而是「這個動作是否符合用戶當初要 agent 做的事情」。如果被擋下，classifier 把理由告訴上層 agent，上層 agent 嘗試找到更安全的替代方案。只有當真的沒有其他路時，才打擾用戶。

這才是正確的互動模型。用戶是最後手段，不是第一關卡。

我在過去一年看過的大多數 agentic 產品都做錯了這件事。要嘛每個有意義的動作都要 confirmation，把用戶訓練成看都不看就點確認；要嘛 agent 有完全自主權，然後某一天做了個不可逆的、你不想要的事。兩個都是治理失敗，只是在刻度盤的兩個極端。

這給每個做 agentic 流程的產品團隊提出了一個設計問題：你的 agent 在刻度盤的哪個位置？在你的產品領域裡，「符合用戶原始意圖」的定義是什麼？哪些動作風險夠低可以直接執行？哪些越過了重要的邊界？

大多數團隊還沒回答過這些問題。他們要嘛繼承了底層工具的全信任預設值，要嘛在感覺「哪裡好像很恐怖」的地方隨機加了 confirmation prompt。兩個都不是設計決策，兩個都只是預設值。

Auto-review 還很早期，目前主要針對本機 desktop agent，相同原則預計會延伸到更多地方。但思考框架是對的，而且可以移植到任何產品。

治理 UX 的問題不是要加更多確認視窗。是要設計一個可以告訴另一個 agent 什麼時候要慢下來的機制。

這是一個產品設計問題。沒有人會幫你解決它。
