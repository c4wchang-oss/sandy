# X Thread — UserTesting MCP（中文）

**主題：** UserTesting MCP Server — research 從驗證步驟變成 context window
**日期：** 2026 年 7 月 22 日

---

**Tweet 1（開場）**
UserTesting 剛發布了 MCP server。

第一眼：一個技術整合更新。
第二眼：這件事改變的是 user research 在 AI workflow 裡發生的時間點 — 從根本上。

(1/8)

---

**Tweet 2**
它在解決的問題：大部分團隊現在用 Figma Make、Claude、ChatGPT 時，帶的是產品需求和設計規格。

沒有 user context。

模型用 pattern 生成，不是用你真實用戶的行為、導航習慣、或流失點。

(2/8)

---

**Tweet 3**
UserTesting MCP 讓你可以直接在 Claude、Figma Make 或其他 AI client 裡招募受測者、建立研究、取得結果。

用戶洞察在生成開始之前就已經載入 — 不是等 prototype 做完才開始。

(3/8)

---

**Tweet 4**
時間點的轉移才是真正的故事。

Research 一直是在想法成形之後才發生的步驟。先做，再驗證。或先調研，再做（理論上）。

實際上，research 通常在方向已經確定、難以改變的時候才到。

(4/8)

---

**Tweet 5**
透過 MCP，你可以在 prompt context 裡載入 user context。

模型的第一輪 output 從更準確的基礎出發。不是 pattern，是你的用戶真實的行為、痛點、流失數據。

第一輪 output 更容易是對的。

(5/8)

---

**Tweet 6**
Figma plugin 的升級也值得記一下。

單一研究可以測試多個 task 和 prototype。不用離開 Figma 就能驗證複雜的多步驟流程。

Research 測試在設計所在的 canvas 上發生。

(6/8)

---

**Tweet 7**
招募規模也很重要：760 萬受測者，320 萬認證專業人士。

過去要一週的招募，現在在 workflow 裡就能完成。問題和答案之間的延遲壓縮了。

AI 生成得快。Research 一直是更慢的那個。

(7/8)

---

**Tweet 8（結尾）**
真正的標題不是「UserTesting 支援 MCP 了」。

而是：沒有 user context 的 AI 只是 pattern matching。

Research 過去是 gate。現在它可以是 context window — 在第一個 prompt 之前載入，不是第一個 prototype 之後。

(8/8)
