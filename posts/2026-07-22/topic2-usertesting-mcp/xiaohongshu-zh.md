---

USERTESTING MCP SERVER — 設計師真正應該關注的那件事

大部分報導把這個當作「技術整合更新」在看。

它不是。

它改變的是 research 在 AI 輔助設計流程中發生的時間點。這比任何功能清單都更重要。

—

🔍 它是什麼

UserTesting 的 MCP Server 讓你可以直接在 Claude、ChatGPT、Figma Make 和其他 AI client 裡招募受測者、建立研究、取得結果。

—

🚨 它解決什麼問題

當你在沒有 user context 的情況下 prompt Figma Make 或 Claude，模型是用 pattern 生成的，不是根據你真實用戶的行為。

它知道好的電商設計長什麼樣。
但它不知道你的用戶會在結帳第三步流失，因為他們不信任地址欄的標籤文字。

Pattern ≠ 你的用戶行為。

—

⏱ MCP 改變了什麼

Research 過去是上線前的最後一步。
→ 設計 → 測試 → 修改 → 上線

有了 MCP，research 可以成為 prompt 的第一個輸入。
→ 載入 user context → prompt AI → 從你的用戶出發，不是從 pattern

你在生成開始之前，把行為數據、過去研究結果、受測者 insights 載入 context window。

—

🖥 Figma Plugin 也升級了

Figma plugin 現在支援在單一研究中測試多個 task 和 prototype。

複雜多步驟流程在設計的 canvas 上直接測試。
不需要匯出，不需要換工具，不需要等 research 交接。

—

📊 讓它變得真實的規模

760 萬受測者，320 萬跨 140 個產業的認證專業人士。

過去要一週的招募，現在在 workflow 裡就能完成。
問題和答案之間的延遲壓縮了。

—

💡 關鍵框架

AI 生成得快。
Research 一直是更慢的那個。
MCP 讓 research 快到能跟上。

Research 不再是 gate，而是 context window。

—

🎯 真正的標題

沒有 user context 的 AI 只是 pattern matching。

UserTesting MCP 讓 research 成為起點，不是驗證步驟。

這改變了 AI 輔助設計真正能產出什麼。
