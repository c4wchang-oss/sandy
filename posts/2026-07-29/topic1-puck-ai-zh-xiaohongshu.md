**標題：** Puck AI：誰決定 AI 在你的產品裡能建什麼？

不是又一個 AI 設計工具，是一個可嵌入的 AI 生成層。

📦 **它到底是什麼**
Puck AI 是開源 React component（GitHub 13k+ stars），嵌入你自己的產品後，讓你的用戶直接在 app 裡用 AI 生成、預覽、調整介面，不需要離開。

兩個模式：
• Assembly 模式 — AI 從你的 component library 選材料組頁面
• Design 模式 — AI 在你定義的 guardrails 裡創造新 components

🏗️ **為什麼這個區分很重要**

Assembly 模式：你的 component library 就是一道牆。AI 生不出你沒建過的東西。不存在 prompt 技巧可以繞過去。生成邊界 = library 邊界。

Design 模式：你寫約束規則，AI 在你定義的語言裡生成。

🎯 **對 product designer 的意義**

1. Component 決策現在就是 AI 生成策略
2. 「應不應該有這個 component？」變成「AI 應不應該能生成這個？」
3. Design system 不再是「參考」，是 AI 創造力的邊界
4. Constraint architecture 現在保護的是你的用戶，不只是你的工程師

🔧 **值得知道的技術細節**
• 輸出是 structured JSON，可版本控管、可存後端
• 有 Headless API 支援程式化批量生成
• 支援 BYOK（自帶 API key）進階控制
• 可以是 chat UI，也可以純程式化接口

💡 **真正的轉變**

定義 component 架構的人，現在在為產品裡每一個用戶定義 AI 生成體驗的可能邊界。

這個設計責任，兩年前根本不存在。
