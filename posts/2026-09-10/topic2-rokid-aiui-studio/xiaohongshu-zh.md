**標題：** 不需要智慧眼鏡，就能設計空間 AI 體驗了 — 但難的部分依然是設計

---

🎯 **發生了什麼：**
2026 年 9 月 9 日，Rokid 在 IFA Berlin 推出 AIUI Studio — 一個在瀏覽器裡就能設計、開發、上架 AI Glasses Agent 的全流程平台。

不需要實體眼鏡，不需要本地開發環境。
用自然語言描述你的 Agent → AIUI Studio 建出 App。
在瀏覽器裡測試：手勢、光線環境、完整互動流程。
一鍵上架到 Rokid AI App 的 Agent 商店。

📌 **AIUI Skills Library 做什麼：**
→ 自動優化眼鏡硬體的延遲
→ 管理裝置上的記憶體限制
→ 平衡電力消耗

平台把硬體限制編進去，讓你專注在互動設計上。

📌 **對 UX 設計師來說，這意味著什麼：**

**開發門檻降低了，設計判斷力的門檻沒有。**

空間 UX 有一些限制，不會因為工具變簡單而消失：

1. **可瀏覽性（Glanceability）**
   半透明顯示，動態情境，實體環境在搶注意力。
   使用者無法停下來閱讀。半秒之內能解讀什麼？

2. **最小干擾原則**
   Agent 什麼時候有權打斷使用者的實體注意力？
   搞錯這個，比搞錯通知時機更嚴重。

3. **漸進揭露**
   對一個在移動中的人，如何分層傳遞信息？
   你不能在眼鏡覆蓋層上放一個 dashboard。

4. **環境感知設計**
   強光讓覆蓋層對比度下降。室內和室外情境完全不同。
   忽視環境的設計，會比你預期更快降級到無法使用。

✅ **現在可以用 AIUI Studio 做什麼：**

1. **把瀏覽器模擬當成設計研究工具，不只是測試工具**
   光線和手勢模擬，會讓你看到自己沒意識到的設計假設。

2. **撰寫 AIUI Skills 時，不只定義硬體限制，也定義互動品質**
   Skills Library 管硬體，但你的 skill definitions 也可以管互動品質。
   寫下可瀏覽性規則，寫下干擾閾值，把空間 UX 原則編進 skill。

3. **優先為「不看螢幕」的互動設計**
   最可靠的空間 Agent 互動，是使用者不需要看它的那種。
   語音 + 細微視覺確認 > 複雜的視覺覆蓋層。

4. **設計「讓人忘記的體驗」**
   好的空間 UX 是隱形的。使用者沒有注意到 Agent 幫他做了什麼。
   壞的空間 UX 才讓人記得。他們感到被打斷、困惑、或視覺不知所措。

⚠️ **誠實的 caveat：**
Rokid 的用戶基數目前有限，你還不是在為大規模空間 UX 受眾設計。
空間 UX 的設計原則在不同耳機之間是可遷移的 — 平台實作不是。
你現在建立的判斷力，就是未來勝出平台出現時適用的判斷力。

💡 **重新框架：**
AIUI Studio 是為一個幾乎還不存在的設計表面建的瀏覽器設計工具。
這正是設計思維最重要的時刻 —
在預設值被設定之前，在其他人跟隨之前。
