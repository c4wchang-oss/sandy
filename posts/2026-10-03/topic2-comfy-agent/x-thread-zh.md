# X Thread — Comfy Agent：ComfyUI 手藝的第一個 Agent（繁體中文）
**主題：** Comfy Agent 在 Comfy Cloud 上線——從文字描述建立、執行和迭代 ComfyUI 圖像/影片工作流，在同一個 canvas 上即時與你並肩工作（2026年10月1日）
**角度：** ComfyUI 的力量一直是 node 層級的控制。整個創作社群都知道它能做什麼——但 node graph 是門檻。Comfy Agent 沒有把 node 抽象掉。它在同一個 canvas 上與你並肩工作。這是一個跟今年所有其他「讓複雜工具變容易使用」方式都不同的產品決策——而且它對我們如何思考 AI agent 協作模型有影響。

---

**Tweet 1 / Hook**
ComfyUI 剛獲得了一個 agent。

它沒有取代 node graph。

它在同一個 canvas 上與你並肩工作。

這是跟今年幾乎所有其他 AI「易用性」故事都不同的產品決策。

---

**Tweet 2**
一些背景：ComfyUI 是認真的 AI 圖像和影片實踐者的工作方式。

基於 node 的工作流。每個模型參數都暴露出來。每個流程步驟都可見且可配置。

這個力量是真實的。門檻也是真實的：你需要了解模型、extensions、node 詞彙。

Comfy Agent 的主張：你不應該必須在野心和複雜性之間做選擇。

---

**Tweet 3**
Agent 實際上在做什麼：

規劃生成技術。一個 node 一個 node 地建立工作流。修復驗證錯誤。推薦適合你任務的模型。找到資產。

處理 5 個並行對話且保留完整歷史——所以你可以同時跑不同的生成方式而不失去脈絡。

而且它在你自己編輯 graph 的同時做所有這些。

---

**Tweet 4**
協作模型是值得研究的部分。

你和 agent 都不等對方。你們同時在同一個 canvas 上工作。

Agent 視覺性地看到 graph。如果你從資源庫拖入一個資產，它注意到了。如果你移動 node，它調整。你可以在對話裡引用任何 node 或另一個工作流。

這不是「生成然後交接」的循環。它更接近一個實踐者和一個理解工具的技術合作者一起工作的方式。

---

**Tweet 5**
Skills 架構跟今年其他所有工具是一樣的模式。

CapCut 8月11日 → Divi 9月5日 → Notion 9月17日 → Figma 9月20日 → Framer 9月22日。

現在 Comfy Agent 把 skills 帶到了圖像/影片生成的 layer。

你在工作時建立公開或私人的 skills。重複使用它們。你內化的 node graph 詞彙成為編碼過的設計判斷——你團隊中的任何人都可以使用。

---

**Tweet 6**
Agent-native 創意引擎的模式再次被確認。

Mirage Tesseract（9月23日）為 agent 重建了影片製作引擎——直接存取 layer、keyframe、mask、timing 等基礎元素。

Comfy Agent 在工作流層做了同樣的事——不是把 AI 貼在工具上，而是一個從根本上理解工具自身詞彙的 agent。

為 agent 重建的工具。不是給工具加上 AI。

---

**Tweet 7**
誠實的部分：

本地 ComfyUI 支援即將推出——現在還沒有。目前僅限 Cloud。

Beta 品質：團隊正在積極除錯和收集反饋。

而且 skills 架構的注意事項在這裡也適用：skills 捕捉你做了什麼，不是你的意圖。發布前要審查。

天花板還是你的 node 詞彙和你的生成 brief 品質。

---

**Tweet 8**
重新框架：

Comfy Agent 是第一個讓 ComfyUI 的完整力量變得可及而不奪走那個力量的工具。

你仍然控制每個 node。Agent 幫助處理一直都是摩擦的部分：知道該用哪些模型、連接工作流、修復減緩創意動力的錯誤。

這就是好的創意協作長什麼樣子：合作者處理技術開銷，讓你可以留在創意問題裡。
