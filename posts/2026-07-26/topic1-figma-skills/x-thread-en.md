**Tweet 2**
A Skill is a Markdown file you write.

You define your team's conventions: which libraries to search first, which variable naming rules to follow, which components to use, how to structure auto layout, when to run accessibility checks.

The agent reads it before every task. Not sometimes. Every time.

---

**Tweet 3**
This is different from a prompt.

A prompt you rewrite every session. It drifts. It gets forgotten. It depends on whoever's in the room.

A Skill is institutional. Permanent. Applied on demand — without you being present.

---

**Tweet 4**
Figma's framing is clean: "Design systems give the agent the right components. Skills layer on the rest of your team's expertise."

That's the split I've been looking for.

System = what to build with.
Skill = how to think while building.

**Tweet 5**
"Constraint architecture" is how I've been describing this for months.

Skills are the most explicit form of it I've seen. You write the constraints into a .md file. The agent ingests them before every task.

Your judgment, enforced consistently, at scale.
