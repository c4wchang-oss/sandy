# Threads Post — Figma Custom Skills：設計文件終於有人讀了
**Platform:** Threads | **Date:** 2026-07-26 | **Language:** 繁體中文

---

我寫設計文件寫了十年。沒人去看的 Notion 頁面。沒人讀的 Figma comment。發布的那一刻就已經過時的 Confluence wiki。

我們為人類寫文件。然後人類忽略它。

Figma Custom Skills 把受眾換掉了。

---

Skill 就是一個 Markdown 文件。你把團隊的慣例寫進去——用哪個 library、遵循什麼命名規則、component 怎麼結構、什麼時候要查 accessibility——然後 agent 在每個任務開始之前都會讀一遍。

不是覺得相關才讀。不是你提醒它才讀。每次都讀。

這個讀者終於現身了。

---

這個隱含的意義比聽起來更讓人不舒服。

如果你沒辦法把設計慣例寫得夠清楚讓 agent 跟隨，只有兩個解釋：要麼你的慣例根本不夠系統化，要麼你對它們的理解還不夠深、說不清楚。

兩種情況都是設計運營的問題。兩種都值得修。

---

Figma 官方的說法很乾淨：「Design system 給 agent 對的 component。Skills 把你的團隊其餘的專業疊加上去。」

Skills 可以編碼品牌語調規則、accessibility 標準、component variant 規範、審查清單——那些活在資深設計師腦袋裡、等他們離職就消失的東西。

讓機構知識可以被移植，這才是被低估的部分。

---

我說「constraint architecture」說了一段時間了。設計工作的核心是定義讓 AI 在其中生成的邊界，而不是做生成本身。Skills 是我見過最明確的實例化形式。

你寫下限制。你做版本控制。你分享給整個團隊。Agent 不帶漂移地應用它們。

---

誠實地說：寫好 Skill 是一個新的紀律。含糊的 Skill 產出含糊的輸出。通用的指令產出通用的結果。精確度的寫作才是工作量真正所在的地方。

大多數設計師沒受過訓練去寫機器可執行的指令。這個落差是真實的。

---

真正的標題不是一個 Figma 功能更新。

是資深設計師的新工作說明。你不只是在設計系統，你在為將要以規模執行你的判斷的 agent 寫課程大綱。

值得坐下來想想的問題：你的團隊 agent 課程大綱現在長什麼樣？
