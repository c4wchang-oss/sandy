**Title:** Figma Skills just made design documentation useful for the first time 📄🤖

---

📌 Bottom line first
Figma Custom Skills = design documentation written for an agent, not a human

Not just a new feature — a different philosophy about who design knowledge is for

🔍 What is a Figma Custom Skill?
A Skill is a Markdown file you write
The agent reads it before every task — every time, without exception

You define:
✅ Which library to search first
✅ Variable naming conventions
✅ Which components to prioritize
✅ Auto layout structure logic
✅ When to run accessibility checks
✅ Brand voice and review criteria

💡 How is this different from a prompt?
Prompt = rewritten every session, easy to drift, depends on who's around
Skill = written once, permanently applied, scales to your whole team

🎯 What this actually means for senior designers

Design knowledge used to live in:
- Notion pages nobody opened
- Figma comments nobody scrolled to
- Your own head (and left when you left)

Skills turn that knowledge into institutional memory — executable, consistent, permanent

⚠️ The honest part
Writing a good Skill is harder than it looks
Vague Skill → vague output
Generic instruction → generic result

If you can't write your conventions clearly enough for a machine to follow them, that's important information about how systematic your design thinking actually is

🏆 How to start (practical steps)
1. Pick your most repeated workflow or your most-explained convention
2. Write it out in plain, sequential steps — as if explaining to a very literal reader
3. Add it as a Custom Skill in Figma
4. Run a task and see where the agent deviates
5. Edit the Skill until it holds

📌 What this signals for design ops

Skills are the new format for design governance:
- Shareable across teams
- Composable (a Skill can call another Skill)
- MCP-ready (will work across Figma and any MCP-compatible client)

Real headline: you now write curriculum, not just specs.
