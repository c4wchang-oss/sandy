# X Thread — Claude Design：「產品設計再往上一層」
**Platform:** X (Twitter) | **Date:** 2026-07-26 | **Language:** 繁體中文

---

**Tweet 1 (Hook)**
打造 Claude Design 的設計師，在趕不上自己的工程師。

不是因為她慢。是因為工程師在以十倍的速度出貨。

所以她打造了一個工具。這個起源故事改變了我對這個工具本質的理解。

🧵

---

**Tweet 2**
Nate Parrott 是 Anthropic 的產品設計師，參與了 Claude Code VS Code extension 的工作。

2024 年底，她合作的工程師「出貨速度遠超以前」。她自己「仍然以一貫的節奏在交付」。

那個速度差，就是 Claude Design 被創造出來解決的設計問題。

---

**Tweet 3**
她建的不是 Figma 的替代品。

她的定位：「產品設計再往上一層」。早期發想。視覺溝通。在工程師動手之前先取得共識。

不是精確到像素的生產 UI，不是最終交付物。是在那之前發生的工作。

---

**Tweet 4**
改變她工作流程的具體能力：你把品牌素材交給 Claude——字型、顏色、component——它生成符合規範的 prototype。每個輸出都自動遵循你的設計系統。

然後你分享一個連結。像分享文件一樣。利害關係人看到它在運作，不是它的截圖。

---

**Tweet 5**
它有機地擴展到了 prototype 以外。

投影片。Landing page。PDF。Email。動畫。社群媒體視覺。

規律：任何需要快速溝通、快速迭代、在被 build 之前可以分享的視覺。那才是真正的產品品類。

---

**Tweet 6**
Claude Code 的整合也圍繞著同一個速度問題設計。

你在 Claude Design 裡探索。準備好 build 的時候，你交給 Claude Code。設計意圖、token、component 選擇都會一起帶過去。工程師不需要重新詮釋——從你停下來的地方繼續。

---

**Tweet 7**
埋在起源故事裡的設計洞察：

瓶頸不是工具，是格式。在 Figma 文件裡工作的設計師產出的工件，以人類速度移動。Claude Design 產出的工件，以模型速度移動。

這個工具改變的是交付節奏，不只是質量。

---

**Tweet 8 (CTA)**
真正的標題：Claude Design 不是為了跟 Figma 競爭而打造的。

是為了縮小設計師和她合作的工程師之間的速度差距而打造的。

這是一個完全不同的問題陳述。也解釋了為什麼這個工具是現在這個樣子。
