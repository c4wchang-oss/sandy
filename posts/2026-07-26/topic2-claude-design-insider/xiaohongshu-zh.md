**標題：** Claude Design 的真實故事：一個趕不上自己工程師的設計師打造了它 ⚡

---

📌 **你需要知道的起源故事**
Nate Parrott，Anthropic 的產品設計師，打造了 Claude Design
不是為了跟 Figma 競爭——是為了縮小她和她合作的工程師之間的速度差距

當更強的模型到來，工程師開始以十倍的速度出貨
她仍然以一貫的節奏在交付
那個差距，就是這個工具存在的原因

🔍 **那 Claude Design 到底是什麼？**
她的定位：「產品設計再往上一層」

它是生產設計之前的視覺層：
✅ 早期發想
✅ 為取得共識的視覺溝通
✅ 在任何東西被 build 之前的可分享 prototype
✅ 投影片、landing page、PDF、動畫

不是：給交付用的精確 Figma 文件
不是：Figma 的替代品

💡 **改變一切的核心機制**
你連接你的品牌素材——字型、顏色、component
每個輸出自動遵循你的設計系統
利害關係人拿到的是可以點擊的連結，不是截圖

不再是「這就是它看起來會是什麼樣子」——他們直接點進去體驗

🎯 **Claude Code 整合如何讓循環閉合**
在 Claude Design 探索 → 在 Claude Code 建構
設計意圖、token、component 隨著交付包一起帶過去
工程師從你停下來的地方繼續
沒有人重新詮釋。沒有人在這個環節丟失保真度。

⚡ **她每天實際用它做什麼**
- 同樣的時間做 15 個 flow 版本，過去只能做一個
- 散步中起草完成 landing page
- 當天早上才知道要報告，當天就有投影片
- 動畫和社群媒體視覺
- 內部一頁報告和電子郵件模板

⚠️ **資深 UX 設計師的誠實評估**
這個工具不適合所有人
如果你的工作完全活在生產級別的 Figma 文件裡，Claude Design 取代不了那個工作流程

但如果你有花時間創建視覺工件，只是為了在東西被 build 之前溝通想法？
那就是這個工具被設計來填補的缺口

📌 **埋在故事裡的設計課**
這個工具是由親身經歷它要解決的問題的人建造的
這就是為什麼 UX 決策感覺對——它們是由一個真的有理由在乎它們是否有效的人做出的
