# Threads Post — Claude Design：為了縮小速度差距而打造，不是為了功能競賽
**Platform:** Threads | **Date:** 2026-07-26 | **Language:** 繁體中文

---

關於 Claude Design，最有趣的不是這個工具，是它的起源故事。

Nate Parrott 是 Anthropic 打造它的產品設計師。她的背景：她是 Claude Code 團隊中少數幾個設計師之一，與工程師並肩工作——然後新的模型到來了，工程師突然開始「以遠超以前的速度出貨」。

她毫不修飾地描述自己的處境：「工程師的出貨量遠超以前，而我仍然以一貫的節奏在交付。」

這不是工具問題。是格式問題。她的工件以人類速度移動。工程的輸出在以模型速度移動。

---

所以她建了一個東西。不是為了取代 Figma——她的定位明確是「產品設計再往上一層」。早期發想。視覺溝通。在任何東西被 build 之前先取得共識。

輸出不是交付文件，是一個可以分享的連結。你給利害關係人一個可以點擊的東西——不是某個最終會能運作的東西的截圖。

---

她實際使用它做什麼：同樣的時間內做出 15 個版本的 flow，過去只能做一個。散步中完成一個 landing page。早上才知道要參加的 pitch，當天就有投影片。動畫。社群媒體視覺。PDF。

共同的線索不是「產品設計」，而是「在值得 build 之前就需要存在的視覺溝通」。這是一個不同、也更誠實的產品品類。

---

Claude Code 的整合讓速度問題的循環閉合了。當一個概念值得去 build 的時候，你交給 Claude Code。設計意圖——token、component、排版決策——都會一起帶過去。工程師不需要重新詮釋。他們繼續。

這個雙向流動不只是為了方便。是為了在最關鍵的時刻不丟失保真度。

---

我一直在思考的一件事：這個工具是由親身經歷它要解決的問題的人建造的。

這比功能清單更重要。意味著 UX 決策是由一個真的有理由在乎它們是否有效的人做出的。

真正的標題：Claude Design 不是 Figma 的競爭者。是對一個具體、真實、個人的「太慢了」的經驗的回應。
