# Threads Post — Cubicle：唯讀設計的 AI agent 辦公室（繁體中文）
**主題：** Cubicle——AI coding agents 的即時像素風辦公室（Claude Code + Paperclip）。MIT 授權，零依賴，唯讀設計。2026年10月3日。

---

## 長篇反思

Cubicle 這週上線了。這是一個為你的 AI coding agents 打造的即時像素風辦公室。Claude Code agents 以像素角色出現在辦公桌前。工作時打字。需要你時舉手。完成時去休息室。

技術實作簡單到近乎滑稽。單一的 Node 檔案，不到 200 行，只用標準函式庫，零 npm 依賴。一個 HTML 頁面。所有東西都在 352×208 的 canvas 上用 fillRect 渲染。沒有圖像、沒有框架、沒有建置步驟。這是那種你可以在十分鐘內完整讀完，然後完全信任的工具。

但值得檢視的產品決策不是實作方式，而是唯讀的限制。

Cubicle 什麼都不能寫。不是因為作者沒有能力做到，而是因為給視覺化工具寫入權限會破壞它試圖提供的東西。一旦觀察者工具可以修改任何東西，它就變成了一個不確定性的來源。你停止信任你正在看的東西。透明度崩潰了。

這是將 constraint architecture 應用到觀察者工具本身。唯讀限制不是對產品的限制——它就是產品本身。

這裡是 Cubicle 實際上在解決的問題，比聽起來更有趣：當你跑一個 AI agent 時，log 沒問題。當你同時跑五個 agents 時，「大家在哪裡，誰在等我？」變成一個空間可視性問題，而 log 在結構上就無法回答這個問題。你無法在周邊視野中同時掌握五條線性時間軸。但你可以掌握一個房間。

像素風格的比喻在做真實的設計工作。姿勢、桌子位置、對話泡泡狀態——這些以比閱讀 log 行更低的認知負擔編碼了 agent 狀態。同樣的原則如同研究顯示，環境監控以零額外注意力比閱讀 chat 記錄減少了 48% 的 AI agent 錯誤。一眼就能看清楚是一種產品價值，而 Cubicle 就是專門為此設計的。

創作者自己的筆記：第一次開啟 Paperclip 整合時，他發現了兩個他不知道存在、他的 agent 一直在等待的問題。這才是真正的使用場景。不是「我想看著我的 agent 工作」，而是「我想在不需要主動檢查的情況下知道我的 agent 是否卡住了」。

共享螢幕上的 kiosk 模式是正確的心智模型。這是為 AI 工作提供的團隊周邊視野。放在房間末端的共享螢幕，讓每個人都能看到是否有事情在等待。

誠實的限制：目前只有 Claude Code 和 Paperclip。Codex 和 Gemini CLI 的 adapter 是開放的 issues。Paperclip 的每個 agent 花費追蹤還沒有。像素風狀態編碼很有魅力，但在你把它當作團隊基礎設施依賴之前，值得對照你的心智模型驗證一下。

重新框架：隨著團隊並行跑更多 AI agents，agent 可觀測性變成了一個 UX 設計問題，而不是一個 logging 問題。設計問題從「agent 完成任務了嗎？」轉移到「團隊中的每個人現在都能看到每個 agent 在做什麼嗎？」Cubicle 用空間比喻回答這個問題。唯讀限制讓答案值得信賴。

本週最誠實的產品決策：一個拒絕碰它正在觀察的任何東西的視覺化工具。
