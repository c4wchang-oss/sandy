## Long-form post

The design-dev handoff has been "broken" for as long as I've been in UX.

Every few years something comes along claiming to fix it. Zeplin. Abstract. Storybook integrations. Design tokens. Each one added a layer of documentation and then watched that documentation go stale.

Figma Code Layers is different. Not because it eliminates the handoff — it doesn't, not really — but because it changes what the handoff is transferring.

Before Code Layers: you handed off a specification. A collection of annotated screenshots describing what should be built.

With Code Layers: you're working in the same artifact as the code. The canvas layer doesn't become a spec. It *is* the thing that runs.

The CPO of Figma said something sharp: they hope Code Layers changes behavior "not just with designers, but also with engineers and PMs." That's the real tell. When the multiplayer canvas is where engineers and designers both make decisions on the same object, the nature of the conversation changes.

What I haven't seen anyone write about: Code Layers doesn't fix a bad design system. If your component structure is messy, undocumented, or full of one-offs — the code that emerges from Code Layers will be equally messy. The quality ceiling hasn't moved. It's still your design system.

The role this creates for senior designers isn't "handoff eliminator." It's "system legibility architect." Making sure the system is structured so that what comes out of it — design, code, or both — makes sense without a 30-minute walkthrough.

Closed beta. Waitlist at figma.com/config-betas. I'm watching this one closely.
