**Tweet 1 — Hook**
Motion design was the last thing an AI agent couldn't touch in Webflow.

That changed Sunday.

/thread

---

**Tweet 2**
Webflow shipped MCP 2.0.

Agents can now build GSAP-powered interactions — scroll triggers, hover states, load animations, multi-step timelines.

From a prompt.

---

**Tweet 3**
And these aren't custom code embeds hidden in the DOM.

They show up in the Interactions panel like anything you'd build by hand.

Edit timing, easing, triggers after — without touching code.

---

**Tweet 4**
The most important design decision in this update:

"The API only builds what the panel itself could build by hand."

Agents can't add anything a human couldn't.

That constraint is good product design. Guardrails create trust.

---

**Tweet 5**
Same update also adds:
→ Faster CMS queries (sort, filter, reference fields in one request)
→ Webflow Cloud app deployment + debugging
→ Branch lifecycle management (Enterprise)

This isn't a small patch. The agent now has the whole site.

---

**Tweet 6**
But here's the real question I'm sitting with:

Motion brief quality is still the ceiling.

"Add a fade in on scroll to each card" = clear prompt.
"Make this feel premium" = not a prompt.

Most of the hard motion decisions are taste problems, not instruction problems.

---

**Tweet 7**
The pattern continues.

Webflow MCP 1.0 → layout + content
Webflow Agent Instructions (Sep 6) → brand constraints
Webflow MCP 2.0 → motion + deployment

Layout, brand, motion, deployment. The agent has it all now.

What it doesn't have is judgment about what the motion should *feel* like.

---

**Tweet 8 — CTA**
That's the senior designer's job.

Not building the interaction.
Writing the brief that makes the agent's interaction not feel generic.

Motion intent documentation is the next DesignOps gap.
