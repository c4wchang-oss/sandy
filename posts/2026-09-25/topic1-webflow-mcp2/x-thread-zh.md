---

**Tweet 2**
Webflow 推出了 MCP 2.0。

Agent 現在可以建 GSAP 驅動的互動效果：
scroll trigger、hover state、載入動畫、多步驟 timeline。

全部從 prompt 完成。

---

**Tweet 3**
這些不是藏在 DOM 裡的自定義程式碼。

它們出現在 Interactions 面板裡，跟你手動建的一模一樣。

時間、easing、觸發條件，之後都可以進去調，完全不用碰程式碼。

---

**Tweet 4**
這次更新裡最好的產品設計決策：

「API 只能建 Interactions 面板本身就能建的東西。」

Agent 沒辦法做任何設計師做不到的事。

有邊界的系統，比沒有邊界的系統更容易建立信任。

---

**Tweet 5**
同一個更新還包括：
→ 更快的 CMS 查詢（排序、篩選、跨集合欄位一次完成）
→ Webflow Cloud 應用部署與 debug
→ 分支生命週期管理（Enterprise）

這不是小修補。Agent 現在掌握整個網站了。

---

**Tweet 6**
但我一直在想的問題是：

Motion brief 的品質還是天花板。

「讓每張卡 scroll 時 fade in」= 清楚的 prompt
「讓這個頁面感覺很 premium」= 不是 prompt，是期望

困難的動態決策是品味問題，不是指令問題。

---

**Tweet 7**
這個模式在繼續：

Webflow MCP 1.0 → 排版 + 內容
Webflow Agent Instructions（9/6）→ 品牌限制
Webflow MCP 2.0 → 動態效果 + 部署

排版、品牌、動態、部署。Agent 全部都有了。

它沒有的，是判斷動態應該「感覺起來像什麼」的能力。

---

**Tweet 8 — CTA**
這才是 senior designer 的工作。

不是自己做 interaction。
而是寫一份讓 agent 的 interaction 不看起來像 generic 的 brief。

Motion intent 文件，是下一個 DesignOps 缺口。
