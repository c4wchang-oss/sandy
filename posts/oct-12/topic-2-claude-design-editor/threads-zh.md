# Threads 貼文 — Claude Design 編輯器控制 + 10/15（繁體中文）

---

**長篇版本：**

我從九月開始追蹤的這個模式，剛完成了又一次循環。

Claude Design 一開始是一個生成靜態 mockup 的獨立網站。現在它是一個可以元素層級編輯的畫布，內嵌在每一個 Claude 對話和每一個 Claude Code terminal session 裡，連接到 14 個下游工具，而且三天後就會對企業團隊預設啟用。

編輯控制的重要性被低估了。拖動、調整大小、對齊、行內文字編輯、間距和顏色的調整滑桿——這解決了「生成之後立刻失去創意控制」的失敗模式，而這個失敗模式一直讓所有真正在乎品質的人對 AI 設計工具感到挫折。你不需要接受模型生成的結果。你可以在畫布上精修，然後交給實作。

Claude Code 裡的 /design 指令是讓這件事變得有趣的地方，從我實際的工作方式來看。你在 terminal 裡，正在建東西。你輸入 /design，Claude 根據你的 design system 生成 artboard，你在瀏覽器裡開啟畫布，你編輯，然後直接推回給 Claude Code 去實作。設計現在發生在開發工作流程的內部，不再是在一個分離工具裡的上游。

Export 連接——Adobe、Canva、Gamma、HyperFrames、Lovable、Miro、Netlify、Replit、v0、Vercel、Wix，共 14 個——讓這件事成為一個平台動作，而不只是功能更新。你的 design system 成為可攜帶的規範，跟著設計一起到每個連接的工具。這是九月的 design.md 可攜性論點在平台規模上的執行。

10 月 15 日是治理時刻。所有企業團隊都預設啟用。如果你是設計主管而且你還沒確認你的 design system 對此的準備狀況，你還有三天。你的組織的 Claude 能產出什麼品質，直接取決於你的 design system 文件有多完善。這不是技術問題。這是 DesignOps 問題。

誠實的複雜性：「所有人都能用」和「所有人都用得好」是不同的問題。治理落差在存取變成普遍的那一刻就打開了。
