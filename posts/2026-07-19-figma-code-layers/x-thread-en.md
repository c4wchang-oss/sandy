# X Thread — Figma Code Layers (English)
**Topic:** Figma Code Layers (closed beta) — executable code as a layer type on the Figma canvas
**Angle:** The canvas absorbs code. The handoff collapses. Design and engineering finally share the same artifact.
**Format:** 8-tweet thread

---

**Tweet 1 (Hook)**
The most significant thing Figma shipped at Config 2026 isn't motion or shaders.

It's Code Layers.

And almost nobody is talking about what it actually means for how design teams work.

Let me explain. 🧵

---

**Tweet 2**
What code layers actually are:

Actual, running code — as a layer type on the Figma canvas.

You clone a GitHub repo. It lives on the canvas. It runs. Your team can see it, comment on it, prompt against it.

Not a screenshot. Not a preview. A working, editable layer.

---

**Tweet 3**
The feature that changes things: "Extract designs."

From any code layer, you convert the current state back into editable Figma layers.

You refine the design. One click updates the code layer with your edits.
When you're done, you push changes back to your repo.

Design → code → design → code. One artifact, one canvas.

---

**Tweet 4**
For a decade, here's how design and engineering have collaborated:

Designer works in Figma. Engineer works in IDE. Handoff is the moment they exchange artifacts.

Every handoff is a translation — and translations lose information.

Code layers collapse the handoff into the canvas. The translation step disappears.

---

**Tweet 5**
What this means for the designer's role is significant:

Before: you design beside the engineer's work.
After: you design on the same artifact as the engineer.

You can annotate a running component, prompt against it for a variation, extract it to design layers, refine it, and push back.

That's not design. That's design + code review in one surface.

---

**Tweet 6**
The uncomfortable truth nobody's saying:

This feature is in closed beta for a reason. Not every team is ready for it.

If a designer edits a code layer — who owns that change? Who reviews it? Who approves the push back to the repo?

These aren't tool questions. They're governance questions. Teams that haven't figured out their design/eng collaboration model will hit these walls fast.

---

**Tweet 7**
What I'm watching for:

Will design leads start reviewing code in Figma instead of in pull requests?

If yes, Figma becomes not just a design tool but an engineering review surface. That's a platform play, not a feature update.

And Cursor, Copilot Workspace, and others just found out their moat is narrower than they thought.

---

**Tweet 8**
Real headline isn't "Figma adds code on the canvas."

It's: Figma is making an argument about where the source of truth lives.

Not the IDE. Not the design file. The shared canvas — where code and design coexist and both teams work.

That's either brilliant or chaotic, depending on how your team is structured.
