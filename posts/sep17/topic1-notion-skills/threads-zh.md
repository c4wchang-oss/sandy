Notion 3.7 這週推出 Skills。表面上：一個可重複使用的 AI 指令共享庫。實際上：這是我第一次看到有產品把「誰最會下 prompt」變成一個組織層面的問題，而不只是個人特質。

我一直觀察到同一個模式。每個團隊都有一個人，找到了讓 AI 真正有用的方式。他有一個把會議記錄變成有用 PRD 的 prompt。他找到了讓 Claude 產出真正像主管簡報的 exec brief 的精確框架，而不是通用摘要。這些知識住在他的對話歷史裡。沒有共享，沒有版本控制。他離開，這些知識就跟著走了。

Skills 是頁面。在 Notion 裡維護。像任何其他頁面一樣有版本控制。團隊最好的工作流程，被編碼一次，由建立者負責維護，整個團隊透過 Notion Agent 使用。管理員可以設定最多 50 個整個 workspace 的預設 skills。每個人都在跑同一個版本。

SKILL.md 可攜性是改變架構的那個細節。在 Notion 建立 skill → 下載 → Claude Code、Cursor、Gemini、Grok 都跟著同一套指令跑。同一個 skill 在你團隊使用的所有 agent 環境裡執行，在一個地方維護。

在你建在這個基礎上之前，兩件事值得誠實追蹤：

下載不會自動同步。橘色 badge 告訴你 skill 更新了，但你還是得手動重新下載。在分散式團隊裡，一定有人一直在跑舊版本。這個 gap 在生產環境裡會造成影響。

Notion Agent 根據你寫的描述自動觸發 skills。自動觸發的準確率等於你的描述品質。描述寫懶了，錯誤的 skill 就會自動觸發，很有自信，不會有任何警告。

還沒有人在命名的新型組織技術債：編碼了過時工作流程的 skills，幾個月後還在執行。跟文件技術債一樣的結構性問題。但更難被發現，因為 agent 不會標記它——它只是很有把握地做了錯誤的事。

角色轉移：你不再是那個寫最好 prompt 的人。你成為建立並維護 skills 庫的那個人。你編碼的東西，成為整個團隊運作的基礎設施。
