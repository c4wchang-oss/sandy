# X Thread — Rivet：平行探索成為工作流基本單位
**Platform:** X (Twitter) | **Date:** 2026-07-25 | **Language:** 繁體中文

---

**Tweet 1（Hook）**
UI 設計的探索成本剛剛被清零了。

Rivet 讓你同時跑幾十個真實介面方向。

不是 mockup、不是 wireframe——是跑在你瀏覽器裡的真實程式碼。

---

**Tweet 2**
它接在你已有的 coding agent 上面工作。

Cursor、Claude、Codex 都支援。

你給一個 prompt 加設計參考（Pinterest、Are.na、本地檔案），它在你專案的隔離分支裡同時 build 每個方向。

---

**Tweet 3**
關鍵機制：每個方向都是真實的 production code。

你在瀏覽器裡並排比較，選出最有潛力的那個，commit 成一個正常的 code change，走標準 PR review 流程。

設計工作流和工程工作流是同一個工作流。

---

**Tweet 4**
為什麼這件事比看起來重要得多：

探索「錯誤方向」的代價，一直是讓資深設計師保守的根本原因。

當大膽的想法需要 3 天才能驗證，你就會停止提出大膽的想法。你開始「預篩選」，稱之為「策略」，但其實是風險管理。

---

**Tweet 5**
Rivet 改變了這個算式。

走錯方向不再有代價。大膽的想法變得理性了。你的團隊創作範圍擴大了——不需要增加人手。

---

**Tweet 6**
但真正的設計洞察在這裡：選擇本身不簡單。

從 30 個方向裡挑對的，正是品味、系統思維、以及使用者洞察真正發揮作用的地方。

這件事無法被自動化。這才是資深設計師的新核心技能面。

---

**Tweet 7**
設計參考的輸入環節常被低估。

你指向的 Pinterest board、Are.na 收藏、本地素材——這些就是你的 context window。

設計判斷上移了：上移到你選擇什麼素材、怎麼提 prompt 這件事上。

---

**Tweet 8（CTA）**
真正的標題不是「AI 幫你設計」，而是：「平行探索成為了工作流的基本單位。」

瓶頸位移了。如何在規模上管理創意選擇，才是現在的核心問題。
