# 小紅書 Post — Figma Design Agent + Weave 10月6日正式 GA（繁體中文）
**主題：** Figma Design agent 和 Weave 工具在2026年10月6日正式 GA——免費 beta 結束，credit 模型啟動，浮動費用和固定費用模型說明

---

**標題：**
Figma Design Agent + Weave 10月6日 GA——「浮動 credit 費用」到底意味著什麼，以及在計費開始前要跑的治理清單

---

**內文：**

Figma 的 Design agent 和 Weave 工具在10月6日結束免費 beta——距今四天。免費實驗窗口正在關閉。以下是在計費開始之前你需要了解和做的事。

**什麼在改變：**

① Figma Design agent 在10月6日開始消耗 AI credits
② Figma Design 中的 Weave 工具在10月6日開始消耗 credits
③ 兩者都從與 Figma Make 和其他 AI 功能相同的共享 credit pool 中消耗

**兩種不同的定價模型——以及為什麼它重要：**

**Weave 工具 = 每工具固定 credit 費用**
可預測。可審計。與 Figma 的圖像 AI 功能相同的結構。對治理有利。

**Design agent = 浮動 credit 費用** 基於：
- 你 prompt 的複雜度
- Agent 為完成任務採取的動作數量
- 你提供的脈絡（連接的 libraries、附加的檔案）

**大多數團隊會錯過的含義：**

更好的 brief 每次 session 消耗更多 credits——但以更少的修改循環更快產出更好的結果。

Brief 品質現在也是 credit 效率。這是同一個優化問題。

描述不清的 prompt 在 agent 解決你的歧義時燃燒 credits。那是雙重費用：更差的產出 + 更高的消耗。

**Figma Workflow Lab 教學（10月1日發布）值得現在閱讀：**

它展示了高槓桿的 Weave 模式——設計系統 Figma 節點作為鎖定的約束 → 生成 → 用於跨5個市場在地化的 Any LLM 節點，配置了市場特定的文案指導原則 → 可編輯的 Figma 圖層作為輸出。

每工具固定費用。可預測的預算。這是 Weave 的 credit 模型對你有利的地方。

**治理清單——在10月6日之前完成：**

✅ 確認你的團隊中誰在免費 beta 期間使用了 Design agent，用於哪些任務
✅ 決定哪些工作流程值得 credit 費用，哪些是探索性的
✅ 在 Figma Admin 設置每用戶 credit 限制（自8月以來可用）
✅ 審計你連接的 libraries——它們的品質影響產出和 credit 消耗兩者
✅ 檢查你的團隊 credit 分配——Professional plan 在8月25日以相同價格獲得了 2 倍更多的 credits

**誠實的說明：**

如果你的團隊中沒有人在免費 beta 期間追蹤 Design agent 使用量，你就沒有可以用來預測費用的使用基準。這個落差值得在接下來四天內處理——即使是非正式地也好。

**資深 UX 的收穫：**

AI 工具治理不是 IT 或財務問題。是 DesignOps 問題。Figma 把 credit 管理工具放在管理員控制台裡。設計領導端的某人需要在10月6日之前擁有那個控制台，而不是之後。
