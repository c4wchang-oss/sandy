**標題：**
Figma 加入了 backend，「設計交付」這個詞快沒意義了

---

**正文：**

Figma 這週加入了 Payload：Figma Make 裡面的完整 backend。

資料庫。檔案儲存。使用者驗證。後台管理面板。API。當你描述 app 的時候，AI 幫你一起架好。

對設計團隊來說，真正改變了什麼：

**Payload 做了什麼：**
① 行銷同事透過內建後台更新文案——不用開工單
② 文案同事發佈文章——不需要開發介入
③ 設計師鎖定版面——權限在工具層就執行了
④ 開發者可以拿 Payload config 自己另外 self-host
⑤ 所有人在同一個系統裡工作

**你現在應該在問的治理問題：**
- 當設計檔案 = CMS，誰核准內容異動？
- 顏色 token 的更新會自動 cascade 到線上版本嗎？
- 誰控制什麼能發佈、什麼時候發佈？

這把設計治理 + 內容治理壓縮進了一個工具。你的流程要在工具之前先跟上。

**對資深設計師的角色轉移：**
你不再在設計交付物了。你在設計權限架構、內容 schema、治理規則。

那是基礎建設設計。還是你的領域——只是搬進了工具裡面。

**誠實說明：**
- 還是 beta，只有美國託管
- GitHub / 本地開發工作流程還不支援
- 複雜的正式對外產品還不適合
- 現在對的範圍：內部工具、行銷網站、早期原型

**更大的圖像：**
Code Layers（設計 → 程式碼在畫布上）+ Specs（Agent 的 brief 層）+ Payload（後端 + CMS）= Figma 不再是交付工具。它是建置管道的起點。「交付」這個概念正在消解。

**結論：**
「從原型到生產」說了好幾年了。Payload 是第一個讓它感覺架構上真實的東西。

你的治理模型準備好了嗎——那才是問題所在。
