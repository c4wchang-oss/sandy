---

🔍 **DESIGN.md 是什麼**

DESIGN.md 是一個純文字檔，用來記錄你的設計系統：

- 顏色 palette 和 token
- 字型比例（type scale）
- 間距規則
- 元件名稱和結構
- 語氣和 voice 指南

人類可以讀。可以用 git 做版本控制。然後——這才是關鍵——你整個 workflow 裡的每個 AI 工具都能讀它。

---

🛠️ **在 Stitch 裡怎麼運作**

1. 把你的設計系統匯出成 DESIGN.md（或自己用 markdown 寫）
2. 每個新的 Stitch 專案在生成任何東西之前都會先讀它
3. 每個畫面、元件或 layout 都被你系統的規則約束
4. 跨專案匯入——不用每次從頭來過

AI 不會偏離你的品牌，因為它有一個可以對照的檔案。

---

🔗 **真正改變你 workflow 的部分**

透過 Stitch MCP server，DESIGN.md 可以帶著走：

→ 把 Stitch 連接到 Cursor、Claude Code 或 Gemini CLI
→ 你的設計系統規則流向你的 coding agent
→ 一個檔案。不需要截圖。不需要對每個工具重新 brief

你的設計 constraint 變成了可攜帶的基礎架構。

---

💡 **從 Senior 設計師的角度，為什麼這很重要**

每個 AI 設計工具都有同樣的失敗模式：你下指令，它生成一個東西。你再下指令，它漂移了。它不記得你跨 session 的 constraint。

DESIGN.md 是一個持久的 contract。不是你每次都要重複的 prompt。是一個放在你 repo 裡的檔案，告訴每個 AI agent 它不被允許做什麼。

這就是「設計系統品質 = AI 輸出品質」在實踐中真實的樣子。

---

⚠️ **誠實的說明**

DESIGN.md 現在是 Google Labs 的提案，還不是標準。其他工具（今天）不讀它。語音功能還是 early stage，有時不夠精準。

但檔案格式提案是生態系轉移的方式。如果 DESIGN.md 被廣泛採用，它可能會成為你整個工具鏈都知道怎麼讀的機器可讀設計系統 contract。

現在就值得關注——不是等所有人都發現之後。
