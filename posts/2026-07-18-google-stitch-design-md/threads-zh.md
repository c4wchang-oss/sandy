# Threads 貼文 — Google Stitch + DESIGN.md（繁體中文）
**格式：** 長篇個人反思 + 有力的觀點
**語氣：** 有深度、無 hashtag、比 X 更個人化的反思

---

Google Stitch 這週做了大改版——無限 canvas、語音輸入、完整的 Agent Manager。Demo 真的很令人驚豔。但我一直在想的是一個小得多的東西：一個叫 DESIGN.md 的 markdown 檔案。

這是我看了幾年團隊在對抗的問題。你定義了一個設計系統——token、元件、字型比例、間距、整套架構。然後 AI 工具生成一個畫面。它帶著全部硬編碼的值進來——顏色是 hex，尺寸是像素，什麼都沒有綁定到你建立的任何東西。每一個 AI 生成的輸出，都在直接破壞你的設計系統結構。

DESIGN.md 是 Google 對這個問題的答案。它是一個純文字檔，用 AI 能讀懂的格式記錄你整套設計系統。你只要寫一次。每個 Stitch 專案都會參照它。每個生成的畫面都被它約束。你可以做版本控制、匯出、跨專案匯入，透過 Stitch MCP server 還能把它傳給 Cursor、Claude Code 或 Gemini CLI，讓你的設計系統規則也流向你的 coding agent。

我一直在告訴各個團隊的事情：問題不是 AI 不會設計。問題是 AI 不知道它不被允許做什麼。DESIGN.md 是那個告訴它的檔案。

這不是一個功能。這是一個檔案格式提案。如果它被廣泛採用——被其他設計工具、IDE、agent 採用——它可能會成為整個設計 ↔ 程式碼生態系的 package.json：一個你整個工具鏈都知道怎麼讀的機器可讀 contract。

「Vibe design」的東西每 18 個月就會演化和改名。一個通用的設計系統檔案格式會持續累積。這是非常不同的兩件事。
