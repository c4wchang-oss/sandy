**Tweet 2**
The headline feature is Component AI authoring.

You can now:
→ Convert existing layers into local components via natural language
→ Swap component instances with a text prompt
→ Override component variables without touching the inspector

Studio AI reads your scene structure and reuses existing variables. Won't create duplicates.

---

**Tweet 3**
Why does this matter?

Until this release, every AI tool in the prototype space worked *around* components.

It could generate screens. Transitions. Interaction logic. But it had no idea what your component architecture looked like. It was working in the dark.

This changes that.

---

**Tweet 4**
The constraint worth knowing:

Studio AI cannot "see" visual design on canvas. It only reads layer structure + property data.

This is actually correct behavior. The AI is operating *inside* your component architecture — not improvising around it.

A system that reads structure is more reliable than one that guesses visuals.

---

**Tweet 5**
The implication that interests me most:

Prototype AI and code AI are now speaking the same language.

ProtoPie's MCP already lets coding agents query prototype scenes, components, variables, and interactions. Now the AI *inside* ProtoPie understands that same component graph.

The design → code pipeline just tightened.

---

**Tweet 6**
Here's the uncomfortable question:

Is your prototype's component architecture clean enough for an AI to navigate?

Inconsistent naming → AI output is inconsistent
Ad hoc variable scoping → AI compounds the mess
No component reuse → AI generates redundancy

Garbage in. Garbage out. But now at prototype speed.

---

**Tweet 7**
What good Component AI looks like in practice:

Describe a state change → AI swaps the component instance
Describe a variant → AI overrides the variable without rebuilding
Describe a pattern → AI reuses what already exists

This is the difference between AI as a generative tool and AI as an architectural tool.
