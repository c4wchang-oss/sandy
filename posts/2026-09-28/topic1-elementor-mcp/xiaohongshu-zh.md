# 小紅書 Post — Elementor MCP：43% 的網站終於有 AI Agent 接口了（繁體中文）
**主題：** Elementor MCP 讓 Claude、Codex、Cursor 直接連到 WordPress 網站（2026年9月23日）

---

**標題：**
43% 的網站終於有了 AI Agent 那層——你的設計系統現在是品質上限

---

**內文：**

WordPress 驅動 43% 的網站。在 Elementor MCP 之前，它是唯一還沒有 agent 原生設計接口的主要 web 平台。

現在 Claude、Codex、Cursor 可以直接在 WordPress 站內建立原生 Elementor 頁面——不是生成程式碼讓你貼上去，是真實可編輯的 Elementor 結構，存為草稿。你在 Editor 裡開啟、審核、準備好了再發布。

**一個 agency 在真實生產網站測試的工作流程：**
Brief → 現有網站 context → Figma 截圖 → 提示詞 → Elementor MCP → 視覺 QA → 手動微調

**Agent 處理 vs 你還是要處理：**
→ Agent：實作
→ 你：IA、視覺層級、accessibility、responsive 行為、設計系統一致性、最終發布

留在人這邊的清單不是限制，是正確的任務分配。

**① 設計系統變成你的品質上限**
Elementor V4 Atomic 給你真正的限制詞彙——classes、variables、states、breakpoints。Agent 在你定義好的東西裡運作。沒有設計系統 = agent 近似。你會立即從輸出裡看見。

**② 發布前草稿的信任模型是對的**
所有東西都以草稿落地，沒有東西在你審核前自動上線。和 Figma Make、Framer canvas、Webflow Actions 同樣的邏輯——生產系統需要人在發布關卡。

**③ 誠實的 V3 / V4 警告**
MCP 目前只支援 V4 Atomic Elements。大多數現有 Elementor 網站跑的是 V3 widgets。你會是混用狀態——新的 Atomic 區塊和舊的 V3 在同一個頁面上。可以共存，但把所有 V3 遷移到 V4 是另一個專案。

**④ 這個收斂值得注意**
Webflow：Agent Instructions（9月6日）→ Framer：Skills（9月22日）→ Elementor：MCP（9月23日）。17 天內每個主要 web 平台都有了 agent 層。

問題不再是哪個平台有了，而是你為 agent 定義了多少設計系統限制可以運作。

---

**說實話：**
Beta 版。目前只有 V4 Atomic，V3 widget 支援之後才來。任何輸出都需要你草稿審核才能發布。

**重新框架：**
WordPress 設計的不一致性積累了好幾年，因為沒有人在看。Elementor MCP 沒有修復那個——它讓每一個缺口在 AI 輸出裡立即可見。你一直在迴避的設計系統稽查，剛變成了一個 AI 品質問題。
