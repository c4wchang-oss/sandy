**Title:**
The Claude Design creator's workflow is nothing like how most people use it — here's what he does differently

---

**Body:**

Nate Parrott, the product designer who built Claude Design, shared his actual daily workflow. It's very different from the typical "describe what you want → tweak → repeat" loop that most people default to.

Here are the 4 core gaps:

**① Wireframes before mockups**
He structures the layout in low fidelity first — before colors, fonts, imagery. The model focuses on composition without also resolving aesthetics simultaneously. Structure → then visual.

Most people skip this. That's why first outputs always need many revision rounds.

**② Real context, not descriptions**
For an existing product, he connects Claude Design to the actual GitHub repo. Or provides brand files, or existing component references. The model has concrete material to build from — not an abstract description to interpret.

Reference beats description. Every time.

**③ Design system as reusable context**
Once he lands on a visual direction that works, he encodes it as a design system. Next session starts from that foundation — not blank slate. Same principle as AGENTS.md, design.md, and Once UI's agent harness (Sep 25): spend thought once, constraint enforces it.

**④ Direct editing for the final 10%**
Claude Design has direct manipulation tools — reorder, resize, edit text, change colors, delete elements. He uses these for final precision refinement instead of re-prompting.

Zero tokens. No new generation cycle. Just manual control where it's actually faster than prompting.

**The universal pattern this reveals:**

Define structure first → provide concrete reference (not descriptions) → generate within bounded space → manual precision edit

I've seen this exact sequence in Figma Custom Skills tutorials, Framer Skills documentation, Vercel design.md, and Google Stitch's brand kit drag-in. The tool changes. The underlying logic doesn't.

**The question for your workflow:**
Where are you currently providing abstract descriptions where concrete references would work?

That gap — between description and reference — is where most AI design quality is lost. And it's entirely in your control.

---

**Honest note:**
This is based on Nate's personal workflow shared publicly — not an official Claude Design tutorial. Adapt to your context; what works for the tool's creator is a starting point, not a recipe.

**The reframe:**
The best AI design workflows don't start with "describe what you want to design." They start with "give the model something concrete to build from." The workflow is the brief. The brief is the constraint. The constraint is the ceiling.
