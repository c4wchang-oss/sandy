**Tweet 1 / Hook**

Thread. 🧵

---

**Tweet 2**
Gap 1: He starts with wireframes, not mockups.

Before colors, fonts, or imagery — he structures the layout in low-fidelity. The model focuses on composition without also resolving aesthetics simultaneously.

Structure first. Then visual detail.

Most people jump straight to visual. That's why the first output always needs so many rounds of revision.

---

**Tweet 3**
Gap 2: He gives real context, not descriptions.

If he's designing for an existing product, he connects Claude Design to the actual GitHub repo. Or uploads brand files. Or provides existing components.

The model has something concrete to build from — not a description to interpret.

Reference beats description. Every time. At every layer.

---

**Tweet 4**
Gap 3: He builds a design system, then reuses it.

Once he lands on a visual direction that works, he encodes it as a design system. Next time, Claude starts from that foundation — not blank slate.

Same principle as AGENTS.md, CLAUDE.md, design.md, Once UI 2.0 agent harness.

Spend thought once. The constraint enforces it.

---

**Tweet 5**
Gap 4: Direct editing for the final 10%, not re-prompting.

Claude Design has manipulation tools — reorder, resize, edit text, change colors, delete elements. He uses those for precision refinement.

Zero tokens. No new generation cycle. Just manual adjustment at the layer where precision matters most.

The last 10% is always the precision problem. Prompting can't solve it.

---

**Tweet 6**
The pattern that emerges:

Define structure first → provide concrete reference, not description → generate within that bounded space → precision-edit manually.

This isn't a Claude Design workflow. It's the architecture of every high-quality AI design workflow I've watched.
