**[Tweet 2]**
What a Skillux pack actually contains:

→ SKILL.md — locked flows, interaction states (hover/focus/empty/error/loading), type scale, spacing rhythm, contrast rules
→ templates/ — reusable structure the agent can reference
→ example-site/ — a runnable sample interface you can inspect before you commit
→ tokens — the visual values SKILL.md points to
→ INSTALL.md — where to put it for each tool

This is not a prompt library. This is a designer's judgment encoded as a machine-readable constraint file.

**[Tweet 5]**
The governance question this raises:

Miro's VibeLab (Oct 26): designer authors skill in-house → defines design system components + usage rules → team runs it on their product.

Skillux: designer purchases skill from marketplace → installs it → agent runs generic UX patterns on their product.

Both extend the same principle. But they represent different answers to: who is responsible for skill quality, and whose judgment is in the system?

---

**[Tweet 6]**
The floor vs ceiling distinction matters here:

Marketplace skills encode generic UX best practices — consistent hover states, appropriate empty states, correct loading patterns, defensible spacing systems. That's the floor.

Your product's visual brand, your design language, your specific component choices — that's the ceiling. No marketplace pack can give you that because it doesn't exist as a generic asset.

Skillux gives you a better floor. It does not raise the ceiling.

---

**[Tweet 7]**
When to use it vs when to author your own:

**Use Skillux when:**
→ Starting a greenfield project without an established design system
→ An AI agent keeps making structural UX mistakes (wrong states, missing flows, broken hierarchy)
→ You need a quick constraint layer for a prototype before the real DS is documented

**Author your own SKILL.md when:**
→ You have brand-specific visual constraints the marketplace can't encode
→ You need agents to work within your actual component library
→ The skill needs to encode your product's specific IA decisions

Good news: Skillux gives you the format either way.

---

**[Tweet 8]**
The reframe:

The open governance question since September has been: "whose skills are authoritative when every tool has its own skill format and no single source of truth?"

Skillux doesn't resolve that. It commoditizes UX best-practice floors. That's valuable — it means less time fixing hover states and more time making product decisions.

But it sharpens the question. The gap between a Skillux floor and a brand ceiling is exactly the value only a senior designer can provide. That's not shrinking.
