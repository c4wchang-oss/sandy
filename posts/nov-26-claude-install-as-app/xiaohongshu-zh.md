# 主題二：Claude「Install as App」— Artifact → 桌面應用程式
# 平台：小紅書
# 語言：繁體中文
# 日期：2026 年 11 月 26 日

---

## 標題
Claude 讓你把 Artifact 安裝成桌面 App 了，真正重要的是它的權限模型

---

## 正文

Claude 在 11 月 24 日在 beta 版推出了「Install as App」。你描述想要什麼 → Claude 建構為 artifact → 在分享選單點「Install as app」→ 它以自己的圖示和視窗住在你的 Dock 中，就像任何其他原生 app 一樣。

不需要打包。不需要程式碼簽署。不需要 API key。使用你的 Claude 帳號。當 artifact 改變時自動更新。

完整情況：

**→ 它是什麼**
人們每天用作工具的 Artifact（會議準備頁面、追蹤器、儀表板）現在可以作為真正的 Mac 或 Windows 桌面應用程式運行——不需要任何傳統的 app 開發流程。

**→ 三個權限層**
預設：和瀏覽器分頁一樣（沒有新的存取）
App 權限：通知、全域快捷鍵、永遠在最上層的視窗、選單欄項目（macOS）、系統匣（Windows）
完整存取：執行程式、讀取/寫入/刪除檔案——不需要每次詢問（需要明確授予）

**6 件值得知道的事：**

1. **權限以版本為單位——這是關鍵的設計決策** — 每次更新（包括你自己的編輯）都重設權限授予並再次詢問。這是正確的。如果你同意的工具在事後默默改變功能，那個「同意」是沒有意義的。每版本重新詢問 = 演化中的工具的正確信任架構。

2. **Artifact 角色正在升級** — Artifact 曾經是「你分享的工作輸出」。現在它們是你依賴的已安裝工具。Brief → artifact → 已安裝工具現在是一個在一個產品內部閉合的序列。

3. **分享連結治理缺口** — 任何有分享連結的人都可以安裝 artifact。對於獨立：低風險。對於團隊：誰管理你的團隊可以以哪個權限層安裝哪些 artifact？產品目前還沒有回答。

4. **完整存取限制適用** — 完整電腦存取（執行程式、讀取/刪除檔案）只適用於你自己撰寫的 artifact，或在 Team/Enterprise 中由組織撰寫的。外部 artifact 會顯示警告。

5. **Team/Enterprise 預設值** — Team：app 功能預設開啟，完整存取關閉直到 admin 啟用。Enterprise：整個功能關閉直到 owner 在組織設定中啟用。在假設可用性之前先確認你的方案。

6. **誠實的前提** — 需要網路連線 + Claude 帳號才能保持開啟（不是本地優先）。Claude Docs、Slides、Sheets 無法安裝。HIPAA 組織和混合部署被排除。從外部網站載入的程式碼可以在不重新詢問權限的情況下改變。

**重新定框：**

這不是「更快建構桌面 app」。

這是第一次，你在對話中描述就建構出的工具，是同一個你從 Dock 執行的工具。沒有中間人。沒有單獨的工程請求。

真正的工作在權限設計中——每版本重新詢問是正確的基礎。在團隊規模上坐落在它上方的治理層仍然是開放問題。
