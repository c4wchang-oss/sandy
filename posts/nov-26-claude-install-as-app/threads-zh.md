# 主題二：Claude「Install as App」— Artifact → 桌面應用程式
# 平台：Threads
# 語言：繁體中文
# 日期：2026 年 11 月 26 日

---

## THREADS 貼文 — 長篇個人反思

Claude 在 11 月 24 日在 beta 版推出了「Install as App」。描述你想要的 → Claude 建構為 artifact → 點擊「Install as app」→ 它從你的 Dock 開啟，有自己的圖示和視窗，就像任何其他原生 app 一樣。

機制本身很直接。不需要打包、程式碼簽署或 API key。App 使用你的 Claude 帳號。當 artifact 改變時自動更新。我覺得更有趣的是權限模型，以及它對 AI 生成工具走向何處的暗示。

三個權限層：預設（和瀏覽器分頁一樣——沒有新的表面積）、App 權限（通知、全域快捷鍵、永遠在最上層的視窗、選單欄項目或系統匣）、以及完整存取（執行程式、讀取/寫入/刪除檔案，不需要每次詢問）。每個層級都需要明確同意。

真正重要的信任決策：權限是以版本為單位。每次更新——包括你自己的編輯——都需要重新同意提示。這是正確的。每次對工具的編輯都改變了工具是什麼。另一個選擇——同意一次，agent 可以默默更新工具的功能——是你同意過一次然後就忘了的勾選框。每版本重新詢問是演化中的工具的正確模型，而且這種信任架構決策在它起作用時是隱形的，在它缺席時是災難性的。

設計 artifact 角色升級值得明確說。Artifact 一開始是「你分享的工作輸出」——一個圖表、一個網頁、一份文件。Anthropic 觀察到人們開始把它們當作日常工作工具：從行事曆和電子郵件提取資料的會議準備頁面、出貨追蹤器。他們的定框：「如果你依賴一個工具工作，它應該像你其他 app 一樣開啟。」Artifact 正在從交付輸出升級為已安裝工具。這是我們在設計 artifact 中更廣泛追蹤的同樣弧線——交付 artifact → agent 約束 → 工作流參數。現在：→ 已安裝工具。

值得說的治理缺口：分享連結 → 任何有連結的人都可以把 artifact 安裝為 app。在 Team 方案，完整存取預設關閉直到 admin 啟用。在 Enterprise，整個功能關閉直到 owner 啟用。對於獨立設計師：明顯的好處，最小的治理表面。對於 30 人的設計組織：誰管理哪些 artifact 可以由哪些團隊成員以哪個權限層安裝？這在產品中還沒有答案。這將是某個人必須回答的問題。

誠實的前提：需要網路連線 + Claude 帳號才能保持開啟（不是本地優先）。完整存取只適用於你自己撰寫的 artifact，或在 Team/Enterprise 中由組織撰寫的。Claude Docs、Slides 和 Sheets 無法安裝。HIPAA 組織和混合部署被排除。如果 artifact 從外部網站載入程式碼，那段程式碼可以在不觸發重新同意的情況下改變——對任何你計劃以提升權限執行的東西，仔細讀那個細則。

權限模型是真正的故事：每版本重新詢問。每次編輯——包括你自己的——都重設權限授予。這是演化中的工具的正確信任架構。
