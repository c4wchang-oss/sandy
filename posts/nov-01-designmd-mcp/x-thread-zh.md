# 2026年11月1日 | Senior UX Designer 視角

---

**推文 1（hook）**
Design system 以前是你從零開始寫的東西。

DesignMD 剛讓它變成你可以瀏覽、比較、remix、fork 的東西。

DESIGN.md 正在跨過那條線，成為基礎設施。

---

**推文 2**
DesignMD 推出了 MCP server（10月27日）。

你的 coding agent 現在可以直接搜索真實 design system 的文件資料庫、並排比較兩個系統、或從任何網站 URL 生成 DESIGN.md——不用離開 Claude Code 或 Cursor。

---

**推文 3**
「Remix」功能才是關鍵的轉變。

從 Discover 資料庫挑一個 design system，調整顏色、字型、圓角、間距，存成你自己的 DESIGN.md，還有可分享連結。

你是在 fork 真實的設計文件，不是從記憶中寫。

---

**推文 4**
這個功能取代了：

→ 對著 Notion 文件從零寫 DESIGN.md
→ 用語言描述 design system 給 agent 聽
→ 一次只從一個網站手動提取 token

Reference over description——應用在 design system 的規模上。

---

**推文 5**
直接在編輯器裡並排比較兩個 design system。

不需要截圖，不需要開瀏覽器，不需要複製貼上。

Agent 做比較，你做判斷。

---

**推文 6**
這個 arc 的完整過程：

Vercel design.md（9月2日）→ Onefold 自動生成器 → GUI.md for code agents → Claude Design 原生 → OpenDesign 17 個 BYOK adapter → 現在：一個可瀏覽、可 fork 的真實文件 design system 資料庫。

「design system 的 npm install」不再只是比喻。

---

**推文 7**
誠實說：

瀏覽 design system ≠ 理解它。

MCP 給你的 agent token 值，不是這些值背後的思路。Spacing scale 是可提取的，但為什麼是這些 spacing、針對什麼受眾、在什麼情境——那還是你要自己寫的文件。

---

**推文 8**
重新框架：

DESIGN.md 從你維護的一個檔案 → 可攜帶的格式 → 一個可瀏覽、可 fork、可分享的資料庫。

這不是產品更新，這是一個格式成為基礎設施的過程。
