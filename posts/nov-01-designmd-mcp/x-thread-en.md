# X / Twitter Thread — DesignMD MCP (EN)
# Nov 1, 2026 | Senior UX Designer POV

---

**Tweet 1 (hook)**
Design systems used to be something you wrote from scratch.

DesignMD just made them something you browse, compare, remix, and fork.

DESIGN.md is crossing the line into infrastructure.

---

**Tweet 2**
DesignMD shipped an MCP server (Oct 27).

Your coding agent can now search a library of real documented design systems, compare two side by side, or generate a DESIGN.md from any website URL — without leaving Claude Code or Cursor.

---

**Tweet 3**
The "Remix" feature is the consequential shift.

Pick a design system from their Discover library. Adjust colors, fonts, corners, spacing. Save it as your own DESIGN.md with a shareable link.

You're forking real documented design work, not writing from memory.

---

**Tweet 4**
What this replaces:

→ Writing DESIGN.md from scratch against a Notion doc
→ Describing your system verbally to the agent
→ Extracting tokens manually from one site at a time

Reference over description — applied at design system scale.

---

**Tweet 5**
Compare two design systems side by side, directly in your editor.

Competitive design intelligence without screenshots, without a browser tab, without copy-pasting.

Your agent does the comparison. You do the judgment call.

---

**Tweet 6**
The arc this closes:

Vercel design.md (Sep 2) → Onefold auto-generator → GUI.md for code agents → native in Claude Design → OpenDesign 17-adapter BYOK → now: a browseable, forkable library of thousands of real documented systems.

"npm install for design systems" is no longer a metaphor.

---

**Tweet 7**
Honest caveat:

Browsing a design system ≠ understanding it.

MCP gives your agent the token values. It doesn't give it the reasoning behind them. The spacing scale is there. Why those spacings, for that audience, in that product context — that's still documentation you have to write.

---

**Tweet 8**
The reframe:

DESIGN.md went from a file you maintain → a portable format → a library you browse, fork, and distribute.

That's not a product update. That's a format becoming infrastructure.

Next question: who's responsible for the brief when your starting point is someone else's remix?
