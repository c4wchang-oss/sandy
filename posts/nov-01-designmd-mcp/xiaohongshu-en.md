## Title
DesignMD just got an MCP server — your agent can now browse real design systems directly

---

## Content

Writing DESIGN.md from scratch used to mean staring at a Notion doc and hoping you captured everything. Not anymore.

DesignMD shipped an MCP server + Remix system on Oct 27. Here's what actually changes in your workflow:

**What you can do in Claude Code or Cursor right now:**

1. **Search thousands of real documented design systems** — The Discover library is searchable from inside your editor, no account needed. Your agent pulls real token structures, spacing scales, and color systems instead of guessing.

2. **Compare two design systems side by side** — Ask your agent to compare the component patterns, spacing logic, or color architecture of any two documented systems. Competitive design intelligence without screenshots or browser tabs.

3. **Generate a DESIGN.md from any website** — Give it a URL, get a structured design system file back. 4 credits, from inside your editor, no browser required.

4. **Remix and fork real work** — Pick a system from Discover, adjust colors, fonts, corners, spacing. Save it as your own DESIGN.md with a shareable link. You start from real documented design decisions, not a blank file.

**Why the MCP matters more than the features:**
Your agent used to approximate your design system from vague prompts. Now it can read a real one — or the most comparable one — directly in context. That's a different quality floor for every output it generates.

**The arc this closes:**
Vercel design.md → Onefold auto-generator → GUI.md for code agents → Claude Design native → DesignMD MCP. DESIGN.md went from a file you write to a library you browse, fork, and distribute. That's a format becoming infrastructure.

**Honest caveat:**
Token values are accessible. Intent behind them isn't. Don't mistake "agent has a design system in context" for "agent understands your design system." The reasoning is still yours to document.

**Senior UX read:**
The question this creates for governance: who is responsible for the brief quality when your starting point is someone else's remix? That's a DesignOps question, not a tool question.
