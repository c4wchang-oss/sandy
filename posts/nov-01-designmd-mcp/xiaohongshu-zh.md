## 標題
DesignMD 推出 MCP server——你的 agent 現在可以直接瀏覽真實 design system

---

## 正文

以前從零寫 DESIGN.md 意味著盯著一份 Notion 文件，希望自己記住了所有重要的東西。現在不用了。

DesignMD 在10月27日推出了 MCP server + Remix 系統。以下是它實際上改變你工作流程的地方：

**你現在在 Claude Code 或 Cursor 裡可以做到：**

1. **搜索數千個真實文件化的 design system** — Discover 資料庫現在可以從編輯器內部搜索，不需要帳號。Agent 拿到真實的 token 結構、間距比例、色彩架構，不再靠猜。

2. **並排比較兩個 design system** — 叫你的 agent 比較任意兩個有文件的系統的組件邏輯、間距結構或色彩架構。不用截圖，不用開瀏覽器，在編輯器裡完成。

3. **從任何網站生成 DESIGN.md** — 給一個 URL，拿回一份結構化的 design system 檔案。4個 credit，不需要開瀏覽器。

4. **Remix 和 fork 真實的設計工作** — 從 Discover 挑一個 design system，調整顏色、字型、圓角、間距，存成你自己的 DESIGN.md 並附上可分享連結。從真實的設計決策出發，不是空白檔案。

**為什麼 MCP 比功能更重要：**
你的 agent 以前靠模糊的 prompt 猜 design system 長什麼樣。現在它可以直接在情境裡讀一個真實的——或最相近的系統。這是所有生成輸出的品質下限的跳躍。

**這完成的 arc：**
Vercel design.md → Onefold 自動生成器 → GUI.md for code agents → Claude Design 原生 → DesignMD MCP。DESIGN.md 從你寫的一個檔案，變成你可以瀏覽、fork、分享的資料庫。這是一個格式成為基礎設施的過程。

**誠實的部分：**
Token 值是可存取的，但意圖不是。不要把「agent 情境裡有 design system」當成「agent 理解你的 design system」。那背後的決策思路還是你要自己寫的。

**Senior UX 的解讀：**
這帶來的治理問題：當起點是別人 remix 的系統，誰來負責 brief 的品質？這是 DesignOps 的問題，不是工具的問題。
